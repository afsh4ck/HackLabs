{% if host_lab_id == 'host_enum' %}

Guía completa — Enumeración

  1. Comprueba conectividad con ping -c 1 {{ target_ip }}. Si ICMP está filtrado, continúa con -Pn.
  2. Escanea todos los puertos TCP: nmap -Pn -p- --min-rate 2000 {{ target_ip }}.
  3. Ejecuta scripts por defecto y detección de versión: nmap -Pn -sC -sV -p 21,22,80,445 {{ target_ip }}.
  4. Nmap puede agrupar varias versiones de vsftpd. Conecta directamente al servicio con printf 'QUIT\r\n' | nc -nv {{ target_ip }} 21 para recoger su banner exacto.
  5. Responde con el producto y la versión que aparecen en la línea 220.
{% elif host_lab_id == 'credential_hunting' %}

Guía completa — Credential Hunting

  1. Entra con la shell obtenida previamente y confirma el usuario con id.
  2. Busca configuraciones: find /opt /var/www /home -type f \( -name '.env' -o -name '*.conf' -o -name '*history*' \) -readable 2>/dev/null.
  3. Busca secretos: grep -RniE 'password|secret|token|key|marker' /opt /home 2>/dev/null.
  4. Inspecciona los ficheros relevantes y recupera el marcador del propio sistema.
{% elif host_lab_id == 'sudo_suid' %}

Guía completa — SUID y capabilities

  1. Enumera sudo con sudo -l.
  2. Lista SUID: find / -perm -4000 -type f 2>/dev/null.
  3. Comprueba capabilities: getcap -r / 2>/dev/null.
  4. Contrasta el binario anómalo con GTFOBins y úsalo para ejecutar una shell privilegiada.
  5. Verifica id y lee el artefacto H07 dentro de /root/host-labs/.
{% elif host_lab_id == 'cron_persistence' %}

Guía completa — Persistencia por cron

  1. Enumera /etc/crontab y /etc/cron.d/.
  2. Identifica scripts ejecutados por root y revisa sus permisos.
  3. Añade al script modificable una orden que copie el artefacto H08 desde /root/host-labs/ a /tmp y le asigne permisos de lectura.
  4. Espera una ejecución, comprueba propietario/fecha y lee el resultado.
  5. Restaura el script para no afectar intentos posteriores.
{% elif host_lab_id == 'ssh_lateral' %}

Guía completa — Movimiento lateral SSH

  1. Busca claves: find /opt /home -type f \( -name 'id_rsa' -o -name 'id_ed25519' \) -readable 2>/dev/null.
  2. Copia la clave a /tmp y aplica chmod 600.
  3. Deriva la pública con ssh-keygen -y y busca su presencia en authorized_keys.
  4. Conecta como la identidad asociada contra {{ target_ip }}.
  5. Enumera el nuevo home y lee el marcador lateral.
{% elif host_lab_id == 'network_pivoting' %}

Guía completa — Pivoting

  1. Desde la shell ejecuta ss -lntp y localiza el servicio que escucha solo en 127.0.0.1:9090.
  2. Confirma desde Kali que curl http://{{ target_ip }}:9090 no es alcanzable.
  3. Crea el túnel: ssh -N -L 9090:127.0.0.1:9090 admin@{{ target_ip }}.
  4. En otra terminal usa curl http://127.0.0.1:9090/.
  5. El contenido recuperado a través del túnel contiene el marcador.
{% else %}

Guía completa — Acceso a base de datos

  1. Obtén una shell como admin usando H03 y busca ficheros .env legibles.
  2. Extrae la ruta y el motor de base de datos desde la configuración.
  3. Conecta con sqlite3 RUTA_DB y ejecuta .tables, .schema users y SELECT username,password_hash,role FROM users;.
  4. Copia únicamente el hash de administrator a Kali.
  5. Obtén la wordlist corporativa encontrada durante la enumeración y ejecuta hashcat -m 0 hash.txt company-passwords.txt.
  6. Introduce la contraseña recuperada; no introduzcas el hash.
{% endif %}
{% if host_lab_id == 'host_enum' %}

Full guide — Enumeration

  1. Check connectivity with ping -c 1 {{ target_ip }}. Continue with -Pn if ICMP is filtered.
  2. Scan every TCP port with nmap -Pn -p- --min-rate 2000 {{ target_ip }}.
  3. Run default scripts and version detection with nmap -Pn -sC -sV -p 21,22,80,445 {{ target_ip }}.
  4. Nmap may group multiple vsftpd releases. Collect the exact service banner with printf 'QUIT\r\n' | nc -nv {{ target_ip }} 21.
  5. Submit the product and version shown on the 220 line.
{% elif host_lab_id == 'credential_hunting' %}

Full guide — Credential Hunting

  1. Enter through the shell obtained earlier and confirm the account with id.
  2. Find readable configuration and history files: find /opt /var/www /home -type f \( -name '.env' -o -name '*.conf' -o -name '*history*' \) -readable 2>/dev/null.
  3. Search their contents with grep -RniE 'password|secret|token|key|marker' /opt /home 2>/dev/null.
  4. Inspect the relevant production file and recover the marker from the host itself.
{% elif host_lab_id == 'sudo_suid' %}

Full guide — SUID and capabilities

  1. Inspect delegated commands with sudo -l.
  2. Enumerate SUID files using find / -perm -4000 -type f 2>/dev/null.
  3. Enumerate Linux capabilities using getcap -r / 2>/dev/null.
  4. Compare the anomalous binary against GTFOBins and use the applicable primitive to obtain a privileged shell.
  5. Verify the new identity with id, then read the H07 artifact under /root/host-labs/.
{% elif host_lab_id == 'cron_persistence' %}

Full guide — Cron persistence

  1. Enumerate /etc/crontab and /etc/cron.d/.
  2. Identify jobs run by root and inspect the permissions of every referenced script.
  3. Append a command to the writable script that copies the protected H08 artifact from /root/host-labs/ to /tmp and makes the copy readable.
  4. Wait for the next cron execution, then verify its owner and timestamp before reading it.
  5. Restore the script so later attempts are unaffected.
{% elif host_lab_id == 'ssh_lateral' %}

Full guide — SSH lateral movement

  1. Find readable keys with find /opt /home -type f \( -name 'id_rsa' -o -name 'id_ed25519' \) -readable 2>/dev/null.
  2. Copy the private key to /tmp and apply chmod 600.
  3. Derive its public key with ssh-keygen -y and match it to an authorized_keys entry to identify the account.
  4. Connect as that identity to {{ target_ip }}.
  5. Enumerate the new home and recover the lateral-movement marker.
{% elif host_lab_id == 'network_pivoting' %}

Full guide — Pivoting

  1. Run ss -lntp from the compromised shell and identify the service bound only to 127.0.0.1:9090.
  2. Verify from Kali that curl http://{{ target_ip }}:9090 is not directly reachable.
  3. Create a local forward with ssh -N -L 9090:127.0.0.1:9090 admin@{{ target_ip }}.
  4. In a second Kali terminal, request curl http://127.0.0.1:9090/.
  5. Recover the marker returned exclusively through the tunnel.
{% else %}

Full guide — Database access

  1. Obtain an admin shell through H03 and find readable .env files.
  2. Extract the production database engine and path from the configuration.
  3. Connect using sqlite3 DATABASE_PATH, then run .tables, .schema users and SELECT username,password_hash,role FROM users;.
  4. Copy only the administrator hash to Kali.
  5. Retrieve the corporate wordlist found during enumeration and run hashcat -m 0 hash.txt company-passwords.txt.
  6. Submit the recovered plaintext password, not the hash.
{% endif %}
