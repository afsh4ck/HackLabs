Objetivo

Se capturó tráfico de red de un segmento sin cifrar. Analiza la captura para extraer credenciales y datos transmitidos en texto claro.

Flag: — la flag está oculta en el propio fichero de evidencia; analízalo y valídala en la caja «Validar Flag» al final de esta página.

{% include 'labs/_forensic_evidence.html' %} {% include 'labs/_forensic_questions.html' %}

Inicio rápido

wireshark captura_trafico.pcap
# o en línea de comandos:
tshark -r captura_trafico.pcap -Y "ftp.request.command==PASS"

1 · Por qué funciona

FTP y HTTP sin TLS transmiten todo en texto claro: usuario, contraseña y cuerpo de las peticiones/respuestas viajan sin cifrar por la red. Cualquiera con acceso al segmento (switch con puerto SPAN, ARP spoofing, Wi-Fi abierta…) puede capturarlo con un simple sniffer.

2 · Abrir la captura

wireshark captura_trafico.pcap

Hay dos conversaciones TCP: una sesión FTP (puerto 21) y una petición HTTP (puerto 80).

3 · Extraer las credenciales FTP

tshark -r captura_trafico.pcap -Y "ftp.request.command==USER or ftp.request.command==PASS" -T fields -e ftp.request.command -e ftp.request.arg

O en la GUI: clic derecho sobre cualquier paquete FTP → Follow → TCP Stream. Verás el usuario y la contraseña en claro.

4 · Extraer el contenido HTTP en claro

tshark -r captura_trafico.pcap -Y "http.response" -T fields -e http.file_data

En Wireshark: clic derecho sobre el paquete HTTP → Follow → HTTP Stream. La respuesta del servidor contiene una nota interna con la flag en texto claro.

Mitigación

  • Sustituir FTP y HTTP por FTPS/SFTP y HTTPS en todos los servicios internos — sin excepciones para "solo tráfico interno".
  • Segmentar la red y restringir el uso de puertos SPAN/mirroring a personal autorizado.
  • Desplegar 802.1X / cifrado a nivel de enlace en redes donde el sniffing pasivo sea una amenaza real.

Herramientas

Wireshark tshark tcpdump

1 · Why it works

FTP and HTTP without TLS transmit everything in plaintext: username, password and the body of requests/responses travel unencrypted over the network. Anyone with access to the segment (a SPAN port, ARP spoofing, open Wi-Fi…) can capture it with a simple sniffer.

2 · Open the capture

wireshark captura_trafico.pcap

There are two TCP conversations: an FTP session (port 21) and an HTTP request (port 80).

3 · Extract the FTP credentials

tshark -r captura_trafico.pcap -Y "ftp.request.command==USER or ftp.request.command==PASS" -T fields -e ftp.request.command -e ftp.request.arg

Or in the GUI: right-click any FTP packet → Follow → TCP Stream. You'll see the username and password in plaintext.

4 · Extract the plaintext HTTP content

tshark -r captura_trafico.pcap -Y "http.response" -T fields -e http.file_data

In Wireshark: right-click the HTTP packet → Follow → HTTP Stream. The server's response contains an internal note with the flag in plaintext.

Mitigation

  • Replace FTP and HTTP with FTPS/SFTP and HTTPS across all internal services — no "internal traffic only" exceptions.
  • Segment the network and restrict SPAN/mirroring port usage to authorized personnel.
  • Deploy 802.1X / link-layer encryption on networks where passive sniffing is a real threat.
