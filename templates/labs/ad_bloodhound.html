Objetivo

Recolecta el dominio con BloodHound y localiza el camino más corto hasta Domain Admins. Un grupo heredado anidado rompe la jerarquía de privilegios: la flag está en su atributo info.

Flag: LDAP · atributo info del grupo anidado — captúrala en el Domain Controller y valídala en la barra lateral.

{% include 'labs/_ad_target.html' %}

Nota sobre este Domain Controller

Los colectores estándar de BloodHound (bloodhound-python, SharpHound) autentican por LDAP con NTLM o Kerberos, y el Samba de este laboratorio corta esa negociación (limitación conocida de Samba AD DC). La ruta de ataque es real y el flag se captura con enumeración LDAP manual (bind simple, que sí funciona) — exactamente lo que BloodHound automatiza por debajo.

Inicio rápido

# Recolectar el dominio (comando real, contra Windows funciona así)
bloodhound-python -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  -ns {{ ad_dc_ip }} -c All --zip

# En este laboratorio, usa enumeración LDAP manual (ver guía completa)
ldapsearch -x -H ldap://{{ ad_dc_ip }} -D 'svc.readonly@{{ ad_realm_lower }}' -w 'ReadOnly123!' \
  -b 'DC={{ ad_realm_lower.split('.')[0] }},DC={{ ad_realm_lower.split('.')[1] }}' \
  '(sAMAccountName=TIER0-LEGACY)' info memberOf

1 · Recolectar el dominio

El colector no necesita privilegios: con cualquier cuenta de dominio lee la información de LDAP y SMB.

# Asegúrate de que el DNS del dominio resuelve (o usa -ns)
bloodhound-python -d {{ ad_realm_lower }} \
  -u 'svc.readonly' -p 'ReadOnly123!' \
  -ns {{ ad_dc_ip }} -dc {{ ad_dc_fqdn }} \
  -c All --zip

Si -c All falla por el módulo de sesiones (necesita SMB en los equipos), usa -c DCOnly: para este dominio es suficiente. El recolector integrado de netexec (nxc ldap --bloodhound) no funciona contra este DC — falla el mismo bind NTLM que el resto de módulos nxc ldap (ver AD 02).

2 · Importar y consultar

# BloodHound CE (Docker)
curl -L https://ghst.ly/getbhce -o docker-compose.yml
docker compose up -d
# → http://localhost:8080  (Administration → File Ingest → sube el .zip)

# BloodHound legacy
sudo neo4j console &
bloodhound

Marca svc.readonly como Owned y lanza las consultas prefabricadas:

  • Find Shortest Paths to Domain Admins
  • Shortest Paths from Owned Principals
  • Find Principals with DCSync Rights

3 · Leer el grafo

El camino que aparece es:

h.jones ──MemberOf──► HELPDESK ──MemberOf──► TIER0-LEGACY ──MemberOf──► DOMAIN ADMINS

Un grupo heredado (TIER0-LEGACY) sigue anidado dentro de Domain Admins, así que todos los miembros de Helpdesk son administradores de dominio efectivos sin que nadie lo haya pretendido. Esta anidación transitiva es exactamente lo que BloodHound existe para encontrar y lo que una revisión manual de grupos casi nunca detecta.

La misma consulta en Cypher, si prefieres la línea de comandos:

MATCH p=shortestPath(
  (u:User)-[:MemberOf|AdminTo*1..]->(g:Group {name:'DOMAIN ADMINS@{{ ad_realm }}'})
) RETURN p

4 · Capturar la flag

La flag está en el atributo info (Notas) del grupo que rompe la jerarquía:

export DC={{ ad_dc_ip }}
export BASEDN='DC={{ ad_realm_lower.split('.')[0] }},DC={{ ad_realm_lower.split('.')[1] }}'

ldapsearch -x -H ldap://$DC -D 'svc.readonly@{{ ad_realm_lower }}' -w 'ReadOnly123!' \
  -b "$BASEDN" '(sAMAccountName=TIER0-LEGACY)' info

# También la ve bloodyAD
bloodyAD --host $DC -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  get object 'TIER0-LEGACY' --attr info

Mitigación

  • Revisar la pertenencia transitiva a grupos privilegiados, no solo la directa.
  • Modelo de niveles (tiering) y grupos administrativos vacíos salvo cuando se necesiten (JIT).
  • Auditar los cambios de pertenencia a Domain Admins (eventos 4728 / 4756).

Herramientas

bloodhound-python BloodHound CE netexec (nxc) bloodyAD SharpHound

1 · Collect the domain

The collector needs no privileges: any domain account can read the LDAP and SMB information it wants.

# Make sure domain DNS resolves (or use -ns)
bloodhound-python -d {{ ad_realm_lower }} \
  -u 'svc.readonly' -p 'ReadOnly123!' \
  -ns {{ ad_dc_ip }} -dc {{ ad_dc_fqdn }} \
  -c All --zip

If -c All fails on the session module (it needs SMB on member hosts), use -c DCOnly: it is enough for this domain. netexec's built-in collector (nxc ldap --bloodhound) does not work against this DC — it hits the same NTLM bind failure as every other nxc ldap module (see AD 02).

3 · Read the graph

The path that shows up is:

h.jones ──MemberOf──► HELPDESK ──MemberOf──► TIER0-LEGACY ──MemberOf──► DOMAIN ADMINS

A legacy group (TIER0-LEGACY) is still nested inside Domain Admins, so every Helpdesk member is an effective domain admin without anyone intending it. This transitive nesting is exactly what BloodHound exists to surface and what a manual group review almost never catches.

The same query in Cypher, if you prefer the command line:

MATCH p=shortestPath(
  (u:User)-[:MemberOf|AdminTo*1..]->(g:Group {name:'DOMAIN ADMINS@{{ ad_realm }}'})
) RETURN p
