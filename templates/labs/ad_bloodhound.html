Objetivo

Recolecta el dominio con BloodHound y localiza el camino más corto hasta Domain Admins. Un grupo heredado anidado rompe la jerarquía de privilegios: la flag está en su atributo info.

Flag: LDAP · atributo info del grupo anidado — captúrala en el Domain Controller y valídala en la caja «Validar Flag» al final de esta página.

{% include 'labs/_ad_target.html' %}

Nota sobre este Domain Controller

Los colectores de BloodHound autentican por LDAP con NTLM (ldap3/Sicily bind, que Samba no implementa) o Kerberos (que aquí falla por un bug real de Samba al firmar el PAC del ticket ldap/{{ ad_dc_host|lower }}). Ninguno de los dos es un límite insalvable: el bind LDAP simple (usuario+contraseña en claro) sí funciona de forma fiable contra este DC — el mismo mecanismo que ya usan ldapsearch/bloodyAD en el resto de labs. Descarga bloodhound_simple_bind.py del share public: es un wrapper de bloodhound-ce-python que fuerza ese bind, y con -c DCOnly (solo LDAP, sin tocar SMB en equipos) hace una recolección completa y real contra este dominio.

Inicio rápido

# Entorno aislado + BloodHound CE (evita romper el bloodhound.py legacy de apt)
python3 -m venv ~/bhce-venv && ~/bhce-venv/bin/pip install bloodhound-ce

# Descargar el wrapper que arregla el bind LDAP contra este DC
smbclient -N //{{ ad_dc_ip }}/public -c 'get bloodhound_simple_bind.py'

# Recolectar de verdad (funciona en vivo)
~/bhce-venv/bin/python bloodhound_simple_bind.py -d {{ ad_realm_lower }} \
  -u svc.readonly -p 'ReadOnly123!' -ns {{ ad_dc_ip }} -dc {{ ad_dc_fqdn }} -c DCOnly --zip

1 · Por qué el colector estándar falla aquí (y cómo se arregla)

bloodhound-python/bloodhound-ce-python solo saben autenticar en LDAP con NTLM o Kerberos (código fuente: bloodhound/ad/authentication.py, método getLDAPConnection). Contra este DC:

  • NTLM — ldap3 usa un bind Sicily que Samba no implementa: LDAPSessionTerminatedByServerError (mismo fallo que nxc ldap, ver AD02).
  • Kerberos — el bind SASL/GSSAPI necesita un TGS-REQ para ldap/{{ ad_dc_host|lower }}; el KDC de Samba falla al firmar el PAC de ese ticket con KRB_AP_ERR_INAPP_CKSUM — un bug real de Samba, verificado en vivo, no de las herramientas cliente.

El bind LDAP simple (DN/UPN + contraseña en claro, sin NTLM ni Kerberos) sí funciona siempre contra este DC. bloodhound_simple_bind.py es un monkeypatch de getLDAPConnection que fuerza ese bind — no toca nada del resto del colector, así que la recolección de usuarios, grupos, ACLs, GPOs y containers es 100% real.

3 · Instalar y levantar BloodHound CE

Guía completa: afsh4ck.gitbook.io — BloodHound. Instala Docker si no lo tienes:

sudo apt install docker.io docker-compose -y
sudo systemctl start docker
sudo systemctl enable docker

# Añadir tu usuario al grupo docker (evita tener que usar sudo con cada comando)
sudo usermod -aG docker $USER
sudo reboot

Este paso es necesario: hay que reiniciar el equipo para que el usuario quede aplicado al grupo docker, o los pasos siguientes fallarán con errores de permisos.

Descarga e instala BloodHound CE con bloodhound-cli (el instalador oficial de SpecterOps, sustituye al antiguo método de docker-compose.yml suelto):

mkdir Bloodhound && cd Bloodhound
wget https://github.com/SpecterOps/bloodhound-cli/releases/latest/download/bloodhound-cli-linux-amd64.tar.gz
tar -xvzf bloodhound-cli-linux-amd64.tar.gz

./bloodhound-cli -h          # menú de ayuda
./bloodhound-cli install     # levanta los contenedores y crea el usuario admin
docker ps                    # confirmar que los contenedores están arriba

bloodhound-cli install imprime en la terminal la contraseña generada para el usuario admin — apúntala, solo se muestra una vez. Para parar/levantar los contenedores más adelante:

./bloodhound-cli containers down
./bloodhound-cli containers up

Accede a la interfaz en http://127.0.0.1:8080/ui/login con admin y la contraseña que te dio la terminal, y sube el .zip en Administration → File Ingest.

Marca svc.readonly como Owned y lanza las consultas prefabricadas:

  • Find Shortest Paths to Domain Admins
  • Shortest Paths from Owned Principals
  • Find Principals with DCSync Rights

4 · Leer el grafo

El camino que aparece es:

h.jones ──MemberOf──► HELPDESK ──MemberOf──► TIER0-LEGACY ──MemberOf──► DOMAIN ADMINS

Un grupo heredado (TIER0-LEGACY) sigue anidado dentro de Domain Admins, así que todos los miembros de Helpdesk son administradores de dominio efectivos sin que nadie lo haya pretendido. Esta anidación transitiva es exactamente lo que BloodHound existe para encontrar y lo que una revisión manual de grupos casi nunca detecta.

La misma consulta en Cypher, si prefieres la línea de comandos:

MATCH p=shortestPath(
  (u:User)-[:MemberOf|AdminTo*1..]->(g:Group {name:'DOMAIN ADMINS@{{ ad_realm }}'})
) RETURN p

5 · Capturar la flag

La flag está en el atributo info (Notas) del grupo que rompe la jerarquía:

ldapsearch -x -H ldap://{{ ad_dc_ip }} -D 'svc.readonly@{{ ad_realm_lower }}' -w 'ReadOnly123!' \
  -b "DC={{ ad_realm_lower.split('.')[0] }},DC={{ ad_realm_lower.split('.')[1] }}" '(sAMAccountName=TIER0-LEGACY)' info

# También la ve bloodyAD
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  get object 'TIER0-LEGACY' --attr info

1 · Why the standard collector fails here (and how it's fixed)

bloodhound-python/bloodhound-ce-python only know how to authenticate to LDAP with NTLM or Kerberos (source: bloodhound/ad/authentication.py, method getLDAPConnection). Against this DC:

  • NTLM — ldap3 uses a Sicily bind Samba doesn't implement: LDAPSessionTerminatedByServerError (same failure as nxc ldap, see AD02).
  • Kerberos — the SASL/GSSAPI bind needs a TGS-REQ for ldap/{{ ad_dc_host|lower }}; Samba's KDC fails to sign that ticket's PAC with KRB_AP_ERR_INAPP_CKSUM — a real, live-verified Samba bug, not a client-tooling issue.

Simple LDAP bind (DN/UPN + cleartext password, no NTLM or Kerberos) always works against this DC. bloodhound_simple_bind.py is a monkeypatch of getLDAPConnection that forces that bind — it doesn't touch anything else in the collector, so the resulting users/groups/ACLs/GPOs/containers are 100% real.

4 · Read the graph

The path that shows up is:

h.jones ──MemberOf──► HELPDESK ──MemberOf──► TIER0-LEGACY ──MemberOf──► DOMAIN ADMINS

A legacy group (TIER0-LEGACY) is still nested inside Domain Admins, so every Helpdesk member is an effective domain admin without anyone intending it. This transitive nesting is exactly what BloodHound exists to surface and what a manual group review almost never catches.
