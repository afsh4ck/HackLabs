Objetivo

La misma muestra de memoria contiene credenciales que nunca deberían quedar en texto claro. Encuéntralas antes de que lo haga otro.

Nota sobre esta muestra de memoria

Igual que en el lab DF14, esta es una muestra reducida pensada para practicar la extracción de secretos por strings/grep — la técnica base detrás de herramientas como mimikatz o pypykatz, que en un volcado real localizan estas mismas cadenas dentro de estructuras de memoria de procesos como lsass.exe. Los comandos de esas herramientas se documentan abajo como referencia.

Inicio rápido

strings memdump_workstation01_lsass.raw | grep -i "PASS:"

1 · Por qué funciona

Muchas aplicaciones "recuerdan" credenciales en memoria mientras el usuario tiene sesión activa — clientes de correo, VPN, gestores de contraseñas mal diseñados. Si esos datos nunca se limpian de la memoria del proceso ni se protegen con técnicas como Credential Guard, un volcado de esa memoria (real o simulado) los expone en texto claro.

2 · Buscar patrones de credenciales

strings memdump_workstation01_lsass.raw | grep -i "CRED_CACHE"

Aparecen varias entradas: tokens de sesión de Teams, una cookie de Chrome guardada… y una que incluye una contraseña en claro.

3 · Aislar la credencial en texto claro

strings memdump_workstation01_lsass.raw | grep -i "PASS:"
# CRED_CACHE|APP:OUTLOOK.EXE|USER:m.director|PASS:Sup3rS3cr3t!|DOMAIN:HACKLABS-CORP

El cliente de Outlook guardó en memoria la contraseña de m.director sin cifrar — un fallo de diseño habitual en clientes de correo antiguos o mal configurados.

4 · (Referencia) Cómo lo harías con un volcado real

# pypykatz sobre un volcado de LSASS real
pypykatz lsa minidump lsass.dmp

# O extrayendo el volcado de un sistema en vivo (con privilegios de administrador)
procdump -ma lsass.exe lsass.dmp
pypykatz lsa minidump lsass.dmp

5 · Capturar la flag

strings memdump_workstation01_lsass.raw | grep -A1 "m.director"
HL{···}

Mitigación

  • Habilitar Credential Guard / LSA Protection en Windows para dificultar el volcado de credenciales en memoria.
  • Nunca configurar clientes de correo/VPN para "recordar contraseña" en texto claro; usar SSO/tokens de corta duración.
  • Restringir y auditar el acceso a herramientas de volcado de memoria (procdump, Task Manager con privilegios) en endpoints.

Herramientas

strings grep pypykatz mimikatz

1 · Why it works

Many applications "remember" credentials in memory while a user session is active — mail clients, VPN software, poorly designed password managers. If that data is never wiped from process memory or protected with techniques like Credential Guard, a dump of that memory (real or simulated) exposes it in plaintext.

2 · Search for credential patterns

strings memdump_workstation01_lsass.raw | grep -i "CRED_CACHE"

Several entries show up: Teams session tokens, a saved Chrome cookie… and one that includes a plaintext password.

3 · Isolate the plaintext credential

strings memdump_workstation01_lsass.raw | grep -i "PASS:"
# CRED_CACHE|APP:OUTLOOK.EXE|USER:m.director|PASS:Sup3rS3cr3t!|DOMAIN:HACKLABS-CORP

The Outlook client stored m.director's password unencrypted in memory — a common design flaw in old or misconfigured mail clients.

4 · (Reference) How you'd approach a real dump

# pypykatz over a real LSASS dump
pypykatz lsa minidump lsass.dmp

# Or dumping it from a live system (with admin privileges)
procdump -ma lsass.exe lsass.dmp
pypykatz lsa minidump lsass.dmp

5 · Capture the flag

strings memdump_workstation01_lsass.raw | grep -A1 "m.director"
HL{···}

Mitigation

  • Enable Credential Guard / LSA Protection on Windows to make credential dumping from memory harder.
  • Never configure mail/VPN clients to "remember password" in plaintext; use SSO/short-lived tokens instead.
  • Restrict and audit access to memory-dumping tools (procdump, privileged Task Manager) on endpoints.
