Objetivo

Un volcado de sectores sin asignar contiene un fichero que fue borrado pero nunca sobrescrito. Localiza su firma y recupéralo por carving.

Flag: — la flag está oculta en el propio fichero de evidencia; analízalo y valídala en la barra lateral.

Inicio rápido

binwalk unallocated_cluster_dump.dd

1 · Por qué funciona

Cuando un sistema de ficheros "borra" un fichero, normalmente solo elimina su entrada del índice/tabla de directorio — el contenido sigue físicamente en el disco hasta que un nuevo fichero lo sobrescribe. El file carving ignora el sistema de ficheros por completo y busca directamente las firmas binarias (magic bytes) de formatos conocidos dentro de un volcado en crudo, recuperando así datos que ya no están "indexados" en ningún sitio.

2 · Localizar firmas conocidas

binwalk unallocated_cluster_dump.dd
# DECIMAL   HEXADECIMAL   DESCRIPTION
# 65536     0x10000       PNG image, 180 x 90, 8-bit/color RGB, non-interlaced
# 65622     0x10056       Zlib compressed data, default compression

binwalk identifica una imagen PNG completa empezando en el offset decimal 65536 — el resto del fichero es ruido aleatorio que simula sectores sin asignar.

3 · Extraer el fichero embebido

# Opción rápida: extracción automática
binwalk -e unallocated_cluster_dump.dd

# Opción manual con dd (funciona siempre, incluso sin soporte de extracción)
dd if=unallocated_cluster_dump.dd of=recovered.png bs=1 skip=65536 count=4096

No hace falta ser exacto con el tamaño: un PNG válido termina en su propio chunk IEND, así que la mayoría de visores/herramientas ignoran los bytes sobrantes después de esa marca.

4 · Verificar y leer el fichero recuperado

file recovered.png
exiftool recovered.png | grep -i comment

La imagen recuperada contiene un comentario PNG con la flag.

Mitigación

  • Borrado seguro (wiping, sobrescritura multipasada o shred/cifrado de disco completo) para datos sensibles que deban desaparecer de verdad.
  • Cifrado de disco completo (FDE): si el volcado en crudo está cifrado, el carving por firma no encuentra nada legible.
  • Política de retención y destrucción certificada de medios de almacenamiento dados de baja.

Herramientas

binwalk foremost photorec scalpel

1 · Why it works

When a filesystem "deletes" a file, it usually only removes its entry from the index/directory table — the content physically stays on disk until a new file overwrites it. File carving ignores the filesystem entirely and searches directly for known binary signatures (magic bytes) inside a raw dump, recovering data that is no longer "indexed" anywhere.

2 · Locate known signatures

binwalk unallocated_cluster_dump.dd
# DECIMAL   HEXADECIMAL   DESCRIPTION
# 65536     0x10000       PNG image, 180 x 90, 8-bit/color RGB, non-interlaced
# 65622     0x10056       Zlib compressed data, default compression

binwalk identifies a full PNG image starting at decimal offset 65536 — the rest of the file is random noise simulating unallocated sectors.

3 · Extract the embedded file

# Quick option: automatic extraction
binwalk -e unallocated_cluster_dump.dd

# Manual option with dd (always works, even without extraction support)
dd if=unallocated_cluster_dump.dd of=recovered.png bs=1 skip=65536 count=4096

You don't need to be exact about the size: a valid PNG ends at its own IEND chunk, so most viewers/tools ignore trailing bytes after that marker.

4 · Verify and read the recovered file

file recovered.png
exiftool recovered.png | grep -i comment

The recovered image contains a PNG comment with the flag.

Mitigation

  • Secure deletion (wiping, multi-pass overwrite or shred/full-disk encryption) for sensitive data that must truly disappear.
  • Full-disk encryption (FDE): if the raw dump is encrypted, signature-based carving finds nothing readable.
  • Retention and certified destruction policy for decommissioned storage media.
