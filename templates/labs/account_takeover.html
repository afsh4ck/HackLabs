Cadena de explotación

  1. Inicia sesión con auditor / Audit2026!.
  2. Consulta GET /account-takeover/api/directory?q=administrator y anota el account_id del objetivo.
  3. Intercepta la petición de actualización de perfil. Sustituye account_id=1002 por el ID del administrador y conserva recovery_email=auditor@hacklabs.local.
  4. Solicita un reset para administrator. El enlace llega ahora al buzón del auditor.
  5. Abre el enlace, fija una contraseña nueva y autentícate como administrator. La aplicación mostrará HL{···}.

Por qué funciona

El endpoint exige autenticación, pero autoriza por el account_id suministrado por el cliente. El reset sí está correctamente vinculado a un token de un solo uso; el takeover nace del cambio IDOR previo.

Mitigación

# Derivar el usuario de la sesión, no del body
target_id = session.user_id
# Reautenticar y verificar el correo anterior/nuevo
# Alertar al correo anterior y revocar sesiones

Exploit chain

  1. Sign in with auditor / Audit2026!.
  2. Request GET /account-takeover/api/directory?q=administrator and note the target account_id.
  3. Intercept the profile update. Replace account_id=1002 with the administrator ID while keeping recovery_email=auditor@hacklabs.local.
  4. Request a password reset for administrator. The link now reaches the auditor mailbox.
  5. Open it, set a new password, and authenticate as administrator. The application reveals HL{···}.

Why it works

The endpoint authenticates the caller but authorizes the object using a client-supplied account_id. The one-time reset token itself is sound; the preceding IDOR creates the takeover.

Mitigation

# Derive the target from the authenticated session
target_id = session.user_id
# Require reauthentication and verify old/new addresses
# Notify the previous address and revoke sessions
