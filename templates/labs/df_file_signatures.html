Objetivo

Un empleado te ha pasado un documento con extensión .docx que "no se abre bien" en Word. Antes de intentar repararlo, comprueba qué tipo de fichero es en realidad — la extensión no siempre dice la verdad.

Flag: — la flag está oculta en el propio fichero de evidencia; analízalo y valídala en la barra lateral.

Inicio rápido

file Informe_Confidencial.docx
xxd Informe_Confidencial.docx | head -5

1 · Por qué funciona

Los ficheros no se identifican por su extensión, sino por sus primeros bytes (los magic bytes o firma de fichero). Un atacante — o en este caso, un empleado despistado — puede renombrar cualquier fichero con cualquier extensión sin que su contenido cambie. Un analista forense nunca confía en la extensión: siempre verifica la firma real.

2 · Comprobar la firma real

file Informe_Confidencial.docx
# Informe_Confidencial.docx: PNG image data, 300 x 150, 8-bit/color RGB, non-interlaced

El comando file reconoce cientos de firmas de fichero. Aquí queda claro que, a pesar del nombre, se trata de una imagen PNG.

3 · Confirmar con los bytes en crudo

xxd Informe_Confidencial.docx | head -3
# 00000000: 8950 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR

La firma 89 50 4E 47 0D 0A 1A 0A es la cabecera estándar de todo fichero PNG — inconfundible.

4 · Renombrar y extraer los metadatos

cp Informe_Confidencial.docx informe.png
exiftool informe.png | grep -i comment

El fichero incluye un chunk de texto tEXt con un comentario — ahí está la flag.

Mitigación

  • Nunca confiar en la extensión declarada por el cliente al validar subidas de fichero (ver también el lab File Upload).
  • Validar el tipo MIME real (magic bytes) en el servidor antes de procesar cualquier fichero.
  • Escanear adjuntos con herramientas de detección de tipo (libmagic) en los flujos de correo/subida.

Herramientas

file xxd exiftool binwalk

1 · Why it works

Files aren't identified by their extension but by their first bytes (the magic bytes, or file signature). An attacker — or in this case, a careless employee — can rename any file with any extension without its content changing. A forensic analyst never trusts the extension: they always verify the real signature.

2 · Check the real signature

file Informe_Confidencial.docx
# Informe_Confidencial.docx: PNG image data, 300 x 150, 8-bit/color RGB, non-interlaced

The file command recognizes hundreds of file signatures. Here it's clear that, despite the name, this is a PNG image.

3 · Confirm with the raw bytes

xxd Informe_Confidencial.docx | head -3
# 00000000: 8950 4e47 0d0a 1a0a 0000 000d 4948 4452  .PNG........IHDR

The signature 89 50 4E 47 0D 0A 1A 0A is the standard header of every PNG file — unmistakable.

4 · Rename and extract the metadata

cp Informe_Confidencial.docx informe.png
exiftool informe.png | grep -i comment

The file includes a tEXt chunk with a comment — that's where the flag is.

Mitigation

  • Never trust the client-declared extension when validating file uploads (see also the File Upload lab).
  • Validate the real MIME type (magic bytes) server-side before processing any file.
  • Scan attachments with type-detection tooling (libmagic) in mail/upload pipelines.
