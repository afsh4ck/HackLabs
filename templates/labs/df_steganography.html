Objetivo

Esta imagen de una puesta de sol esconde algo más que píxeles. Analiza sus bits menos significativos para recuperar el mensaje oculto.

Flag: — la flag está oculta en el propio fichero de evidencia; analízalo y valídala en la caja «Validar Flag» al final de esta página.

Inicio rápido

# zsteg no está en los repos de apt de Kali -- es una gema Ruby
sudo gem install zsteg
zsteg sunset.png
# o con Python + Pillow (ver guía completa)

1 · Por qué funciona

La esteganografía LSB (Least Significant Bit) oculta datos modificando el bit menos significativo de cada byte de color de una imagen. El cambio es tan pequeño (como máximo ±1 en un canal de 0-255) que resulta invisible al ojo humano, pero perfectamente recuperable si sabes dónde mirar.

2 · Intentar con herramientas estándar

zsteg no está empaquetado para apt en Kali — es una gema Ruby, se instala con gem:

sudo gem install zsteg
zsteg sunset.png

Entre la enorme lista de combinaciones que prueba (bit-plane × canal × orden), una acierta directamente:

b1,rgb,lsb,xy       .. text: "HL{···}"

binwalk sunset.png no sirve aquí: busca ficheros incrustados o datos anexados al final del fichero, no datos ocultos en el bit menos significativo de cada píxel — con esta técnica solo confirmará que el PNG es válido y no encontrará nada más, lo cual es normal y no significa que el reto esté roto.

steghide extract -sf sunset.png nunca funcionará aquí: steghide solo soporta JPEG, BMP, WAV y AU — ni siquiera reconoce PNG como formato de entrada (falla con el formato del archivo no es reconocido sea cual sea el contenido del PNG). No es un problema de instalación ni de esta imagen en concreto.

Si prefieres no depender de zsteg, puedes extraer el mensaje manualmente: este reto usa un LSB casero (bit menos significativo del canal R, G y B en orden, con un prefijo de 32 bits indicando la longitud del mensaje en bytes) — exactamente la combinación b1,rgb,lsb,xy que zsteg también prueba por defecto.

3 · Extracción manual con Python

python3 - <<'EOF'
import struct
from PIL import Image
img = Image.open('sunset.png')
pixels = list(img.getdata())

bits = ''
for px in pixels:
    for c in px[:3]:
        bits += str(c & 1)

length = int(bits[:32], 2)
msg_bits = bits[32:32 + length*8]
msg = bytes(int(msg_bits[i:i+8], 2) for i in range(0, len(msg_bits), 8))
print(msg.decode())
EOF

El script lee el bit menos significativo de cada canal de color, reconstruye primero la longitud del mensaje (32 bits) y después el mensaje en sí.

4 · Capturar la flag

HL{···}

Bonus · Ocultar tu propio mensaje con LSB

La operación inversa: en vez de leer el bit menos significativo de cada canal, lo sobrescribes con los bits de tu mensaje. Mismo esquema que en el reto — prefijo de 32 bits con la longitud, luego el mensaje byte a byte, LSB del canal R, G y B en orden:

python3 - <<'EOF'
from PIL import Image

message = b"HL{tu_mensaje_secreto}"
img = Image.open('portada.png').convert('RGB')
pixels = list(img.getdata())

length_bits = format(len(message), '032b')
msg_bits = ''.join(format(b, '08b') for b in message)
bits = length_bits + msg_bits

new_pixels = []
bit_idx = 0
for px in pixels:
    px = list(px)
    for c in range(3):
        if bit_idx < len(bits):
            px[c] = (px[c] & ~1) | int(bits[bit_idx])
            bit_idx += 1
    new_pixels.append(tuple(px))

img.putdata(new_pixels)
img.save('oculto.png')
EOF

Dos detalles que importan: la imagen de portada necesita al menos (32 + len(mensaje)*8) / 3 píxeles (un bit por canal, tres canales por píxel) para poder alojar el mensaje completo, y el fichero de salida tiene que guardarse como PNG (u otro formato sin pérdida) — cualquier compresión con pérdida como JPEG recalcula los valores de los píxeles y destruye el LSB. Puedes comprobar que funciona pasando oculto.png por el script de extracción del paso 3, o por zsteg (detecta la misma combinación b1,rgb,lsb,xy que usó este reto).

Mitigación

  • No es un control técnico habitual — la esteganografía es difícil de detectar de forma genérica.
  • En entornos sensibles, aplicar recompresión/resize de imágenes subidas por usuarios (destruye el LSB) antes de servirlas.
  • Usar DLP (Data Loss Prevention) con análisis estadístico de LSB en flujos de salida críticos.

1 · Why it works

LSB (Least Significant Bit) steganography hides data by altering the least significant bit of each color byte in an image. The change is so small (at most ±1 on a 0-255 channel) that it's invisible to the human eye, yet perfectly recoverable if you know where to look.

2 · Try standard tools first

zsteg is not packaged for apt on Kali — it's a Ruby gem, install it with gem:

sudo gem install zsteg
zsteg sunset.png

Among the huge list of combinations it tries (bit-plane × channel × order), one hits directly:

b1,rgb,lsb,xy       .. text: "HL{···}"

binwalk sunset.png won't help here: it looks for embedded files or data appended to the end of the file, not data hidden in the least significant bit of each pixel — with this technique it will only confirm the PNG is valid and find nothing else, which is expected and doesn't mean the challenge is broken.

steghide extract -sf sunset.png will never work here: steghide only supports JPEG, BMP, WAV and AU — it doesn't even recognize PNG as an input format (fails with the file format ... is not supported no matter what the PNG contains). It's not an installation issue or specific to this image.

If you'd rather not depend on zsteg, you can extract the message manually: this challenge uses a home-made LSB scheme (least significant bit of the R, G, B channels in order, with a 32-bit prefix indicating the message length in bytes) — exactly the b1,rgb,lsb,xy combination zsteg also tries by default.

3 · Manual extraction with Python

python3 - <<'EOF'
import struct
from PIL import Image
img = Image.open('sunset.png')
pixels = list(img.getdata())

bits = ''
for px in pixels:
    for c in px[:3]:
        bits += str(c & 1)

length = int(bits[:32], 2)
msg_bits = bits[32:32 + length*8]
msg = bytes(int(msg_bits[i:i+8], 2) for i in range(0, len(msg_bits), 8))
print(msg.decode())
EOF

The script reads the least significant bit of each color channel, first reconstructing the message length (32 bits) and then the message itself.

4 · Capture the flag

HL{···}

Bonus · Hiding your own message with LSB

The reverse operation: instead of reading the least significant bit of each channel, you overwrite it with your message's bits. Same scheme as the challenge — a 32-bit length prefix, then the message byte by byte, LSB of the R, G and B channels in order:

python3 - <<'EOF'
from PIL import Image

message = b"HL{your_secret_message}"
img = Image.open('cover.png').convert('RGB')
pixels = list(img.getdata())

length_bits = format(len(message), '032b')
msg_bits = ''.join(format(b, '08b') for b in message)
bits = length_bits + msg_bits

new_pixels = []
bit_idx = 0
for px in pixels:
    px = list(px)
    for c in range(3):
        if bit_idx < len(bits):
            px[c] = (px[c] & ~1) | int(bits[bit_idx])
            bit_idx += 1
    new_pixels.append(tuple(px))

img.putdata(new_pixels)
img.save('hidden.png')
EOF

Two details that matter: the cover image needs at least (32 + len(message)*8) / 3 pixels (one bit per channel, three channels per pixel) to fit the whole message, and the output file must be saved as PNG (or another lossless format) — any lossy compression like JPEG recomputes pixel values and destroys the LSB. You can confirm it works by running hidden.png through the extraction script from step 3, or through zsteg (it detects the same b1,rgb,lsb,xy combination this challenge used).

Mitigation

  • Not a common technical control — steganography is generically hard to detect.
  • In sensitive environments, recompress/resize user-uploaded images (destroys the LSB) before serving them.
  • Use DLP (Data Loss Prevention) with statistical LSB analysis on critical outbound flows.
