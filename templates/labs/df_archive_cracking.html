Objetivo

RRHH protegió un informe financiero con una contraseña débil antes de subirlo por error a una carpeta pública. Craquéala offline para acceder al contenido.

Flag: — la flag está oculta en el propio fichero de evidencia; analízalo y valídala en la caja «Validar Flag» al final de esta página.

{% include 'labs/_forensic_evidence.html' %}

Inicio rápido

zip2john Informe_Financiero_Q3.zip > hash.txt
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
{% include 'labs/_forensic_questions.html' %}

1 · Por qué funciona

El cifrado tradicional de ZIP (ZipCrypto) es criptográficamente débil y, además, la contraseña elegida es una palabra común de diccionario. Un atacante no necesita romper el cifrado: le basta con probar millones de contraseñas candidatas offline hasta encontrar la correcta.

2 · Extraer el hash crackeable

zip2john Informe_Financiero_Q3.zip > hash.txt
cat hash.txt
# Informe_Financiero_Q3.zip/Informe_Financiero_Q3.txt:$pkzip$1*1*2*0*...

3 · Crackear con john + rockyou

john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
john --show hash.txt

En segundos, john encuentra la contraseña dentro del diccionario rockyou.txt.

¿Te sale No password hashes left to crack (see FAQ)? No es un fallo — significa que ese hash ya está crackeado en tu potfile local (~/.john/john.pot), de una ejecución anterior tuya. john nunca vuelve a intentar un hash que ya tiene resuelto. La contraseña sigue ahí, solo hay que pedírsela con --show:

john --show hash.txt
# Informe_Financiero_Q3.zip/Informe_Financiero_Q3.txt:trustno1:Informe_Financiero_Q3.txt:Informe_Financiero_Q3.zip::

1 password hash cracked, 0 left

Si de verdad quieres forzar un re-crackeo desde cero (por ejemplo, para comprobar el tiempo que tarda), borra la entrada de ese hash del potfile o usa john --pot=otro_fichero.pot ... con un potfile nuevo.

4 · Abrir el archivo

unzip -P '<contraseña_encontrada>' Informe_Financiero_Q3.zip -d extraido/
cat extraido/Informe_Financiero_Q3.txt

El informe descomprimido contiene la flag.

5 · Capturar la flag

HL{···}

Mitigación

  • Nunca proteger datos sensibles solo con la contraseña de un ZIP — usar cifrado fuerte real (GPG, AES-256 con contraseña robusta) o, mejor, control de acceso a nivel de almacenamiento.
  • Forzar políticas de contraseñas robustas y comprobarlas contra diccionarios conocidos (rockyou, HaveIBeenPwned) antes de aceptarlas.
  • Auditar y eliminar ficheros con datos sensibles en ubicaciones de acceso público.

Herramientas

zip2john john the ripper hashcat rockyou.txt

1 · Why it works

Traditional ZIP encryption (ZipCrypto) is cryptographically weak, and on top of that the chosen password is a common dictionary word. An attacker doesn't need to break the encryption — they just need to try millions of candidate passwords offline until they find the right one.

2 · Extract the crackable hash

zip2john Informe_Financiero_Q3.zip > hash.txt
cat hash.txt
# Informe_Financiero_Q3.zip/Informe_Financiero_Q3.txt:$pkzip$1*1*2*0*...

3 · Crack with john + rockyou

john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
john --show hash.txt

Within seconds, john finds the password inside the rockyou.txt dictionary.

Getting No password hashes left to crack (see FAQ)? That's not a failure — it means this hash is already cracked in your local potfile (~/.john/john.pot) from a previous run of yours. john never retries a hash it already has an answer for. The password is still there, just ask for it with --show:

john --show hash.txt
# Informe_Financiero_Q3.zip/Informe_Financiero_Q3.txt:trustno1:Informe_Financiero_Q3.txt:Informe_Financiero_Q3.zip::

1 password hash cracked, 0 left

If you genuinely want to force a fresh crack from scratch (say, to time it), remove that hash's entry from the potfile, or use john --pot=another_file.pot ... with a brand new potfile.

4 · Open the archive

unzip -P '<found_password>' Informe_Financiero_Q3.zip -d extracted/
cat extracted/Informe_Financiero_Q3.txt

The decompressed report contains the flag.

5 · Capture the flag

HL{···}

Mitigation

  • Never protect sensitive data with just a ZIP password — use real strong encryption (GPG, AES-256 with a strong passphrase) or, better yet, storage-level access control.
  • Enforce strong password policies and check them against known dictionaries (rockyou, HaveIBeenPwned) before accepting them.
  • Audit and remove files containing sensitive data from publicly accessible locations.

Tools

zip2john john the ripper hashcat rockyou.txt
